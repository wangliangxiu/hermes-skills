# 编写施工组织设计（技术标正文）

> **数字与例子声明：文中出现的数字、面积、间数、台数、天数、时限、表名、章节号、项目名都是举例**，
> 一律以**本次招标文件**的原文为准。凡是牵扯到数据的地方（工期天数、节点日期、面积、间数、人数、
> 机械台数、材料规格与等级、报审时限、各类比例）都要回本次文件原文逐个核 ——
> 不能把别处抄来的数、或这里举例的数，当成本次的要求写进去；文件没写的就不写，拿不准的进问题报告。

## 什么时候用它

- 要写施组正文了（招标文件已经扫完、章节已经按格式要求搭好）
- 用户说：做技术标、投标施组、施工组织设计、这一章怎么写、方案部分怎么写

不适用：扫招标文件（用 bid-tender-scan）；整份投标文件的章节、格式、附表与编完复查（用 bid-document-writing）。

## 四条现实，先接受

1. 时间是硬约束：一个月、半个月、最短一周都可能。目标不是每句都写漂亮，而是在期限内交出一份
   章节齐全、评分点齐全、格式不违规的标。任何取舍，先保这三样。
2. 评判依据只有一样：**本次招标文件**。它怎么要求，就怎么写 —— 实际情况（比如工人其实是外包的）
   不改变"答什么"，只影响你怎么把它答圆。
3. 数字要经得起推：没有半个人、半台机械。
4. **招标文件里的这些要求（工期节点、材料范围与规格、驻地与临建面积、程序与报批、文明环保、
   文物古树保护……）都是底线**：写施组、写每一份施工方案时都要当成不能碰的红线 ——
   方案里不能出现与它们冲突的地方（文件说甲供的写成自采、文件给的面积你在图上排小了、
   文件指定关键线路法你另写一套排法，都是冲突）。
   这一条里凡是数的地方都一样：数按本次文件，别用别处的数（下面提到的一切数字都只是打比方）。

## 先认清承包模式：施工总承包 ≠ EPC

管理模式跟着**承包模式**走 —— 使用者 2026-09-16 提醒：**总包管理方式和 EPC 管理方式不一样**。
动笔（尤其第二章组织架构与管理方案）之前，先看清招标文件要的是哪种：

- **施工总承包**（市政 / 地铁 / 铁路土建标最常见）：**只管施工**。设计与施工分离（设计由建设单位
  另委），投标只要求施工资质；典型结构是"**项目总承包部 + 工区项目部**"两级管理；计价按清单
  （单价 / 总价按施工图），计量按实际完成量，地质、设计原因一般可走变更；管理重心在施工组织、
  对各专业分包的管理、与业主 / 设计 / 监理的外部接口、甲供与乙供材料的界分。
  铁路标里还常见"**施工单价承包**""施工总价承包"这类叫法（同一族，只是计价方式不同）
- **工程总承包（EPC / 设计施工总承包）**：按《房屋建筑和市政基础设施项目工程总承包管理办法》
  （建市规〔2019〕12号）第三条 —— 承包单位对**工程设计、采购、施工或者设计、施工等阶段实行总承包**，
  并对**质量、安全、工期和造价全面负责**。要点：
  - 要求**同时具备设计资质和施工资质**，或由设计单位与施工单位组成**联合体**（定牵头人、
    协议明确责任权利、对建设单位承担连带责任）
  - 计价：企业投资项目**宜采用总价合同**，总价一般不予调整（除合同约定可调情形）→
    设计优化、限额设计、变更控制成了自己的事
  - 风险分担有约定：主要材料 / 设备 / 人工价格波动超幅部分、法规政策变化、不可预见的地质条件、
    建设单位原因、不可抗力由建设单位承担
  - 管理上要"**建立与工程总承包相适应的组织机构和管理制度**"，形成**设计、采购、施工、试运行
    管理**以及质量、安全、工期、造价、节能环保的综合管理能力；要**加强设计、采购与施工的协调、
    完善和优化设计**；常设设计管理部、采购 / 设备部
  - 项目经理资格更宽（注册建筑师 / 勘察设计注册工程师 / 注册建造师 / 注册监理工程师，或高级职称），
    且不得同时在两个项目担任
  - 质量、安全均**对全部工程负总责**，承担质量终身责任；对总进度和各阶段进度负责
- **单价承包**等其他模式：按单价结算，管理重心落在计量支付与工序验收上
- 另外还有 **联合体投标 vs 单独投标** 的区别：联合体要写牵头人、成员单位分工、"法人管项目"、
  上级指挥部；单独投标就写公司本部管控（公司直管、企业技术中心 / 研究所支持之类）

**别串味**：施工总承包标里塞"限额设计""设计优化"，或 EPC 标里只写施工组织、不写设计与采购管理，
都是答非所问。**部门设置、管理制度、管理措施三者都要跟承包模式对齐**。

**这个区别落到施组正文上怎么表现**（第二章最明显）：

- 施工总承包：组织机构写"总承包部 + 工区项目部"，部门里**不设设计管理部 / 采购部**；
  管理方案写施工组织、分包管理、接口管理（与设计是**外部接口**）、计量与验收
- EPC：组织机构要体现**设计管理与设计衔接岗、采购 / 设备岗**；管理方案要写**设计进度与设计接口管理、
  设计优化与限额设计、采购与设备供货计划、设计与施工的融合（可施工性）、试运行管理**；
  接口管理主要是**内部协调**（设计—采购—施工之间）
- 把这一条与前面"承包体制决定机构称谓"合起来看：**模式定机构、机构定职责、职责定管理方案**，
  三层必须一条口径（这也是全文"前后不矛盾"最容易翻车的地方）

## 第 4 步 圈"必须重写清单"，先圈后写

不要逐段判断"这段要不要改"，那样最费时间。只找哪些必须重写：

- 措施跟着工法走：这次是盾构，质量、安全措施就不能留桥梁或地上那套
- 体系是管理框架，可以整段沿用（质量保证体系、安全保证体系）
- 风险 / 重难点：招标文件里已经列出的（第七章"工程重难点"那张表）一条不能漏，逐条给对策；
  其余优先从图纸里筛（有的图纸直接给了风险源）
- 工程量清单看"开项"不看数量

## 第 5 步 施工方案那一章怎么写

- **按施工顺序写，不按清单的单位工程分**。
  例（地下车站为主的项目）：桩基础 → 围护结构 → 基坑开挖 → 主体结构施工 → 回填；
  写完再往下写盾构区间怎么做、盾构区间的施工方案。车站与桥梁分开之后，各按一条顺序往下走。
- **施工顺序直接从招标文件里拿**：工程量清单那一章末尾常附一份《工程量清单项目及计算规则》附表，
  它按工法分节（明挖（盖）挖 / 盾构区间 / 桥梁拆复建 / 前期专项 / 高架区间 / 高架车站……），
  节内一级项目的排列本身就是施工顺序，写施组时按这个顺序来即可，不用自己猜。
  例（以实际文件为准）：明挖＝围护结构 → 土石方工程 → 主体结构 → 防水工程 → 杂散电流及综合接地；
  桥梁拆复建＝拆除 → 基础 → 下部结构 → 上部结构 → 附属 → 桥面铺装 → 便桥；
  高架区间＝土石方 → 基础 → 下部结构 → 上部结构 → 附属 → 顺路、改沟 → 综合接地。
- 施工顺序理不清、想不起某个工序该怎么做 → **用工具去查"这个活该怎么做"**，查清楚再落笔。
  （工具是查单个工序怎么干，不是拿去定整章顺序 —— 顺序按上一条的附表来）
- 重复内容不重写：写"参照第 X 章第 X 节 XX 内容"。
  例：河道回填与基坑回填分开写，内容相同时用"参照"引过去。
- 土石方不只有开挖和回填，还可能牵扯交通导改（导改涉及河道回填的也要算进去、写上）。
- 前期专项工作实施方案：照清单里"前期专项"那部分的开项写 —— 清单里有什么，前期工程就写什么
  （前期清单里有交通导改、桥梁拆复建，前期工程部分就要写上导改方案、桥梁拆复建方案）。
- 工程量清单的用法：把各单位工程"分部分项工程和单价措施项目清单"（表-08 那类）的开项汇总去重，
  做成"本标段要干哪些活"的底单，再拿它对照施组查漏。总价措施项目那类不用管。

## 开头怎么写（工程概况那一段）

不管看图纸总说明、看招标文件的工程概况，还是写施组的开头，**顺序基本是固定的三段**：

1. **工程概况**：项目名称、工程大致情况 —— 建设地点、规模（线路长度、车站数、主要工程内容与数量）、
   起讫里程、承包方式这类
2. **一张平面缩略图**：画着工程的**地理位置**，并且把工程的**走向**画出来 ——
   桥梁、铁路、隧道沿哪个方向走、起讫在哪、在图上是怎么一条线
   （施组里那张"工程位置图"就是从这儿来的：**项目介绍开头必须有一张**）
3. **周边环境**：沿线都有什么、离工程多远。**设计图给了就照着写；没给全就自己查**
   （地图软件、街景、公开资料），一条条找、每条都落到"**与工程红线（或结构边线）的距离**"：
   - 工程经过的路口：**几车道、限速多少**（经过哪个路口就查哪个）
   - 河道 / 河湖 / 水系（有没有、哪条、多宽）
   - 铁路线（有没有、哪条运营线）
   - 国道 / 省道 / 高速公路（等级、距离）
   - 地标性建筑与重要单位（车站、商场、学校、医院、政府机关……）
   落笔写成清单式：对象 / 基本情况（几车道、限速、等级、规模）/ 与红线的距离 / 对施工的影响
4. 这三段后面才是**工程地质与水文地质**（层序、分布特征、水文、岩土评价）——
   怎么写、上哪儿取、怎么摘，前面已经说清了（摘一小段带过，见"篇幅往哪砸"那节）
5. **气象条件**（气温、降水、风、灾害性天气）一般也有，就在设计总说明的
   "建设条件 / 自然条件"里、挨着水文地质那一节；**有就写上，没有就先不写**（别自己编）

落笔顺序就照它走：先把"这是条什么线、怎么走、周边是啥"讲清楚，再往地质、重难点、方案深入。

## 总体目标及保证措施怎么写

- **目标**从哪来：招标文件"工程目标"那一节 + 合同条款（质量等级、工期违约、奖罚创优）+
  招标公告与须知的工期 + 第八章内容清单（要写哪些目标）—— 几处不一致就取大值都写上
- **保证措施跟目标一一对应，一个目标配一节**。例（某版施组共十节）：
  安全保证措施 / 质量保证措施 / 工期保证措施 / 环境保护保证措施 / 文明施工保证措施 /
  内业管理保证措施 / 内外关系保证措施 / 信息化管理保证措施 / 科技研发与应用保证措施 / 职业健康保证措施
- **每节 2~6 条；每条分两层写**（这是使用者 2026-09-16 讲的写法）：
  - **第一层"大条"**（一两句）：**承诺 + 机制 + 动作 + 兜底** —— 例："以招标文件给定的总工期和
    节点工期为红线（承诺），实行倒排工期、逐级分解到工区与车站区间、编里程碑与关键节点计划、
    责任到人（机制），按周检查按月考核、滞后立即分析原因并纠偏（动作），确保不迟于、
    力争提前（兜底）"
  - **第二层"具体措施"**：在大条下面挂 ①②③④ 若干条，把怎么干写实 ——
    例（工期）：逐站逐区间建节点台账、滞后部位增加工作面与班组、盾构提高有效掘进时间、
    车站增加模板支架套数多段平行流水、关键工序专人跟班与日进度通报
  - 大条管方向，具体措施管落地；两条之间不许"大条下面没措施"或"只有措施没有主张"
- 这一层是"**总体**"承诺：**提纲式，一两句一条**；细的措施留到后面的专章（质量章、安全章、
  文明环保章）—— 别在这儿就把后面章的内容搬过来，那样重复又占篇幅
- 只写能承诺的（例："无条件服从招标文件设立的总工期节点要求"），不写空话
- **措施内容从哪来，两个来源**：
  1. **网上搜** —— 同类工程的保证措施写法、要引的规范与地方要求（如扬尘防治、标准化管理那类）
  2. **参照手上的投标文件** —— 拿往期那版（例：某标 779 页那版）对着改：把工程类型、地点、
     目标值、工法换成本次的
  参照来的稿子必须逐句过一遍，**"照抄不动"的地方恰恰最容易出错**。要换的至少这几类：
  - **地名 / 地区称呼**：原稿写"严格执行国家、扬州、业主、总承包项目部……制定的相关制度"这类话，
    地名要换成本工程所在地，业主称谓、机构名称（总承包部 / 工区项目部 / 指挥部）也要按本次项目的叫法改
  - **一切地方性要求都要换成工程所在地的** —— 不只是地名：地方规范与标准、地方主管部门、
    地方性的环保 / 扬尘防治 / 标准化管理 / 渣土消纳 / 水土保持这些规定，原稿是哪个城市的就叫哪个城市的，
    换到新地方要整段替换（一个项目在扬州、下一个可能在别处，照抄就会答错）
  - 工程名 / 项目名 / 旧标段名、旧里程与旧目标值（工期天数、质量目标、节点日期）
  - 旧工法留下的措施（这次是盾构，原稿可能写着桥梁或地上那套）
  - **机构设置要按本次项目的实际**：有的项目**没有"总承包项目部"这一层**
    （只设项目部 / 工区，或只有项目经理部），别把原稿那套"指挥部 + 总承包部 + 工区项目部"照搬下来 ——
    层级和叫法按招标文件的要求（人员资历要求表、组织机构格式表）加上公司自己的组织实际来定。
    **根子在承包体制**：招标文件要求总承包（一个承包商管全标段、再分若干工区）才会有"总承包部 / 工区项目部"；
    **不是总承包制，全文就不能出现"总承包项目部"这类称谓** ——
    而且不只是组织架构那一章，后面各章（质量、安全、进度、协调配合……）里凡是"总承包部负责……"
    的句子都要一起改，**全文称谓必须统一**
  - 暗标项目：投标单位名称、人名、徽标与文档属性里的身份信息，一并清掉
  做法：先列一张**替换对照表**（旧词 → 新词），替换完再用旧词搜一遍（旧地名、工程名、机构名逐个搜），
  搜不到了才算过 —— 这一步别省

## 内容的三个来源，以及"按逻辑编"的边界

写任何一节，按这个顺序找料：

1. **网上搜** —— 同类工程的写法、要引的规范与地方要求
2. **参照手上的投标文件**（往期最好那版）—— 对着改：工程类型、地点、目标值、工法、机构称谓、
   地方性规定（详见上一节的替换清单）
3. **搜不到、参照里也没有 → 按逻辑自己编**：可以编，但守住边界

**能编的（按逻辑推）**：

- **结构**：照招标文件要求的分块与评分标准那几条（要"体系完整、措施有力"，就写体系 + 措施 + 检查考核）
- **句式与套路**：谁负责（岗位 / 部门）+ 依据什么（文件、制度、体系、规范类别）+ 做什么动作 +
  怎么检查考核，一条一句，可执行
- **内容**：用**本次工程的已知条件**填空 —— 工法（盾构 / 明挖 / 高架 / 桥梁）、地质（富水软土、
  承压水）、结构形式、工区与节点、周边环境（路口几车道、限速、河道、既有建构筑物）、
  本次文件里的硬要求（驻地面积、报审时限、文明环保那几块）
- **常识性措施**：由工法与风险推出来的常规做法（泥浆与渣土处置、扬尘防治六个百分百、噪声与振动控制、
  基坑分层开挖及时支撑、盾构始发到达加固与监测、联络通道安全门、管片拼装质量控制……）

**不能编的（必须查或留给人）**：

- **数字与参数**：承载力、沉降与变形限值、允许偏差、进度指标、人员机械数量（数量要么照文件、
  要么按取整规则算并标注）
- **规范号与条文**：不能凭印象写 GB/标准编号，要么查到准确编号，要么写"按现行国家 / 行业规范执行"
- **地方性规定**：哪个城市的扬尘、标准化、消纳办法，没查到就不点具体文号
- **承诺性数字**：没定的（如创优目标、科研项数）不能自己许

**编完要交付的东西**：稿件 + 一份"**待核清单**"（哪几句是按逻辑编的、哪些数字 / 文号需要核实），
标清给人复核 —— 按逻辑编出来的稿是"可用的初稿"，不是终稿。

## 1.3 工程特点、重难点及对策怎么写

### 工程特点（1.3.1）：逐条列，一句定性 + 一句展开

**结构**：5~8 条，每条 = **一句"判断式"小标题**（先定性）+ **一到两句展开**（塞本次工程的事实与数字）。
例（某版施组的 5 条）：

1. 工程周边环境复杂，影响因素多 —— 富水软流塑地质条件、沿线制约因素多、周边环境复杂、工期风险大
2. 工程规模大，管理跨度大，施工精度要求高 —— 线路长 30.40km，涵盖路基、桥梁、隧道，专业多、交叉作业频繁
3. 大跨连续梁跨越既有公路、河道，结构复杂、施工难度大 —— 特殊结构梁多（支架现浇简支箱梁、
   道岔连续梁、悬臂现浇梁、系杆拱、索加劲连续梁），技术复杂、工期紧、任务重
4. 环境保护要求高 —— 约 67% 线路为地面或高架段、途经大量居民区，噪声振动与房屋开裂易引发投诉
5. 征迁量大，影响施工进度 —— 沿线建（构）筑物密集，下（侧）穿 110KV 高压铁塔、酒店、民宅、
   小区、加油站、过水箱涵、桥梁、河道、市政道路，协调难度与施工风险大

**写法要点**：

- 小标题用**判断句**：某某复杂 / 规模大 / 难度大 / 要求高 / 量大 —— 先定性，读者一眼知道是什么特点。
  常用的几个定性词：**施工工艺复杂**（不常见结构、特殊工法、组合工法一多，就用这句概括）、
  结构形式多样、技术标准高、施工精度要求高、管理跨度大、制约因素多、环保要求高 ——
  后面再列举具体结构与工艺撑着
- 展开里放**本次工程的真事实**：里程与长度、结构类型清单、百分比、下穿/侧穿对象清单、地质描述、
  工区与车站数量 —— 都从招标文件（工程概况、工区划分、清单开项）、勘察报告、自己查的周边环境里来
- **不常见的特点也要写上**（使用者 2026-09-16 明确）：规模大、环境复杂这类常规特点人人会写；
  **本次工程特有的、不常见的那些更要点出来** —— 特殊结构形式与罕见工法、超常规的限制条件
  （邻近营业线、跨越通航河道、高压线走廊、下穿既有构筑物、文物保护、特殊地质……），
  这些才是体现"这是本标段"的地方。
  例（某地铁 / 市域铁路标）：**矮塔斜拉桥（索加劲连续梁）、系杆拱桥**这类不常见结构，
  **大直径超长桩**、盾构 + 明挖 + 高架组合的区间、联络通道暗挖 —— 工艺不常见的，都算特点，
  一条条点出来（这类特点往往同时就是后面的重难点）
- **不只是"写"，还要"分析"**（使用者 2026-09-16 明确）：每条特点不能只描述完就走，
  要顺着分析它**意味着什么** —— 难在哪、影响什么（工期 / 质量 / 安全 / 协调 / 成本）、
  会带来哪些风险。这层分析就是"特点 → 重难点 → 对策"的桥：
  特点里的客观事实 → 分析出难点 → 1.3.2 里配对策
- 特点本身只做**客观描述，不写对策**（对策留给 1.3.2）
- 特点 → 难点 → 对策是一个台阶：**特点里"难"的那几处，就是 1.3.2 重难点的来源**，
  所以特点写完回头看一遍，别把真正难的东西漏在特点里

### 重难点分析及对策（1.3.2）：用一张汇总表，逐条"难点 → 对策"

**难点从哪来（都要扫，扫完汇总成一张清单，先别去重，去重容易漏项）**：

1. **招标文件第七章"工程重难点"那张表** —— 主来源：按车站 / 区间 / 车辆基地逐个列
   "自身风险 / 环境风险 / 前期拆改难点"，**一条都不能漏**
2. **图纸** —— 有的图纸直接给风险源、控制因素
3. **岩土勘察报告** —— 地基均匀性、不良地质与特殊性岩土（软土、承压水、液化）→ 支撑"自身风险"
4. **周边环境** —— 沿线建构筑物、管线、河道、道路、铁路线 → 支撑"环境风险"
5. **前期专项清单开项** —— 交通导改、管线迁改、桥梁拆复建、道路改移 → 支撑"前期拆改难点"
6. **工程特点那一节**里已经点出来的（大跨梁、始发接收、超长桩、联络通道……）
7. **评标办法**里"控制工程和重难点工程"这类评分项 —— 提示要写到什么深度

**对策怎么写**：

- 一条难点配一条（或一组）对策，对策要写**自己的施工对策**：
  招标文件那张表里的"施工要求"那列可以接着用；**"设计控制措施"那列是设计口径，不能照抄当自己的对策**
- **对策不能只看招标文件给的信息** —— 文件给的是"难在哪"和设计口径，**具体怎么干得自己想**：
  按本次的工法、地质、结构、场地、资源和工期，定出工序安排、加固与降水方式、设备选型、
  监测预警、组织与防护措施；需要时借鉴同类工程的做法（翻往期标、查资料），再落到本工程
- 自检一句：把对策里的"**设**"（设计给的做法）和"**干**"（我们要做的动作）分开 ——
  只有"设"没有"干"，等于没写对策
- 每条对策落到"怎么干"（工法选择、加固与降水、监测与预警、组织与防护），别只写"加强管理"
- **招标文件列的重难点之外，还要自己补**（使用者 2026-09-16 明确"还要加上一些其他可以施行的内容"）：
  - **补充重难点**：本标段实际里我方能识别、能应对的其他重难点 —— 工期紧的部位、资源与工作面限制、
    多单位协调、交通组织、季节施工（汛期 / 冬季）、征迁与管线制约这类，招标文件不一定列全
  - **补充措施**：配套的**可施行**内容 —— 能落地的动作、可操作的流程 / 制度 / 资源安排
    （谁干、什么时候干、用什么资源、怎么检查）
  - 自检一句：这条措施**照着能不能干**？答不出"谁、何时、拿什么干"，就是空话，删掉或写实
- 用汇总表呈现（难点分析 | 主要对策），表格写不下再在表后分条展开

## 篇幅往哪砸：前面带过，后面才是重点

工程概况、地形地貌与水文地质这类"场地底子"，**一笔带过就行**（例：某 779 页的施组，
工程概况里的地质那块就是"地形地貌两三句 + 一张工程地质层分布特征表 + 水文地质一段"，
地质资料怎么摘见 bid-tender-scan 技能的 `references/图纸册与勘察报告怎么用.md`）。

**篇幅砸在重点章上**：工程特点与重难点及对策、主要施工方案、质量 / 安全 / 风险管理措施。
参考某 779 页施组的篇幅分布：第三（实施与施工方案）章约 270 页，接近全书一半；
管理类章每章 20~50 页；智慧工地、劳材机各 60 页上下。
写的时候先按本次招标文件的页数要求把额度分好：前面带过、后面写透。

## 第 6 步 力气砸在这三处

通用章节套一下就行，这三处不能糊：

1. 项目介绍（开头必须有一张工程位置图）
2. 现场施工平面布置图
3. 工期与进度计划

## 图怎么来：优先复用，能少改就少改

使用者 2026-09-16 明确：**图不用从头画 —— 拿现有的改，能少改就少改**。前提是**与本次内容不冲突**
（工法、机构与工区数、材料与目标口径都对得上），有项目名称变化就把名字改成本次的。

**现有图的四个来源**（按省事顺序）：

1. **往期投标文件的文档里**（最常用）：Word 里那些图多数是**嵌入的 Visio 对象 —— 双击就能进 Visio 改**
   （本机装了 Visio）；也可以从 docx 里把嵌入对象抠出来（`word/embeddings/Microsoft_Visio_Drawing*.vsdx|.vsd`），
   用 Visio 或脚本改字
2. **纯图片（EMF / PNG / JPG）**：EMF 是**矢量**，插进 Word 后可以"**取消组合**"改字（改完还是矢量）；
   PNG / JPG 是位图，改字得重画或用图片软件处理
3. **指导性施工组织设计 / 招标文件**里给的图（铁路标常见），可以直接拿
4. **自己画**：Visio COM 脚本（本技能 `scripts/org_chart_visio.py`、`flow_visio.py`），
   出的也是 .vsdx 原生文件，后期照样在 Visio 里改

**认图的办法**：从 docx 里导出嵌入对象后，`.vsdx` 是 zip，读 `visio/pages/page*.xml` 里的 `<Text>`
就能认出这张图画的是什么、有没有旧项目名字（脚本见桌面工作副本的图库清单做法）。

**一份施组里一般要有这些图**（按招标文件要求取舍）：

- 两张图：工程位置（地理位置）图、现场施工平面布置图
- 组织机构图（项目部 / 总承包部 + 工区）
- **质量管理流程图、安全管理流程图**（使用者强调这两张最重要）+ 进度、风险等流程图
- 各体系图：质量保证体系、安全（生产）保证体系、风险管理保障体系、文明施工与环保管理体系、
  消防保卫与健康保证体系

## 收尾：先出一份核查提醒

检索一圈之后，给一份三类清单：

1. 已核查、没问题 —— 查过并确认的
2. 已核查、但不确定 —— 查了但拿不准的（图片里的字看不清、某个字样算不算识别性信息）
3. 智能提醒（要人做的）—— 盖章、签字、骑缝、装订、密封、U 盘与光盘份数、平台上传递交；
   其中需要去落实确认的一类：招标文件里明确写了数量 / 型号的大型设备（最典型的是盾构机台数），
   提醒标书编制人员及时跟**机械部门或机械设备厂家**沟通 —— 台数、机型 / 直径、进场与到达时间、
   自有还是租赁，别照着自己想象写（盾构机到达时间不满足工期，有的项目直接算无效标）。
   同一类还要提醒人复核的：**组织机构与岗位职责** —— 岗位设置有没有缺岗、部门名称与职责边界
   是不是符合**本公司实际与招标文件要求**（尤其搜来 / 参照来的岗位职责，口径得由他们确认）；
   这块是公司口径的事，写稿人别替他们定，出稿时列入"请编标人员核对"一栏

**提醒要分三层，别一律写"请编标人员核对"**（使用者 2026-09-16 提醒：有的是要**投标单位（公司）**
定的，**编标人员很多时候自己也确定不了，他只起联络作用**）：

- **编标人员自己能定的**：格式与篇幅、章节与目录、往期稿的替换与清理（地名、项目名、暗标信息）
- **要联络公司（投标单位）拍板的**：岗位设置与部门设置、资源投入与人员机械配置、公司层面的
  管控措施与制度、联合体的牵头人与分工、创优目标这类承诺、**投标单位资质等级与业绩、
  拟派主要人员的姓名 / 证书 / 履历**（招标文件常要求"主要人员资历要求表"）—— 清单要写清
  "**要谁答、答什么**"，好让他直接转达给公司相关部门
- **要联络外部单位的**：机械设备厂家（台数 / 机型 / 到场时间、自有还是租赁）、材料供应商、
  设计单位（接口与图纸问题）

一份清单里把这三层分开写，编标人员拿去就能分头问；模糊地写一句"请核对"，往往就卡在他那儿了

**哪些不用写、不用管**（使用者 2026-09-16 明确，省得白费功夫）：

- **公司内部文件**（管理规定原文、制度文件全名）—— 不用去要，也不必细写；制度**名目**照招标文件
  要求列（招标文件要哪些管理制度，就列哪些）即可
- **专家顾问组的具体专家名单** —— 公司定，标书里写专业方向与合作单位类型即可，不列具体人名
- **指挥长的具体人选** —— 不写那么细；写清**层级与构成**（由哪一级领导担任、成员由哪些单位领导组成）
  就行，非要确定的话提醒编标人员去跟公司沟通
- **创优目标不要自己定级** —— 照招标文件要求的质量目标 / 创优要求写，不自己加码写"鲁班奖"这类

另外，扫文件过程中遇到的**前后不一致 / 两处说法不同 / 拿不准的地方**，全都写进问题报告：
指清是哪两处（章节、页码）、各写的是什么，让标书制作人员关注这个地方 ——
不要自己闷头判一个口径就算了，哪怕判断下来是"同一件东西的两种叫法"，也要提出来。
（要对外向招标人发问的，走第二章要求的澄清程序，注意澄清截止日期，过了就不受理了）

自己能核的直接核：暗标（搜投标单位名称、人员姓名、其他项目名称、徽标照片标识，连同文档属性）、
唯一报价（技术标里不该出现报价数额）、联合体（协议书、牵头人）、章节与招标要求是否一致、
工期有没有超、两张图齐不齐、格式细则逐条过了没有。

## 常见坑（施组侧）

- 逐段判断"这段要不要改"最费时间 → 改成先圈必须重写的
- 用往期标当模板时工程类型不同（地上 / 桥梁 ↔ 盾构 / 地下），措施整段照搬就答非所问
- 施工方案照清单的单位工程分节，写成"按标段照抄"，而不是按施工顺序展开
- 只按自己习惯排工期，忘了招标给定的施工期限是硬上限；节点不按车站 / 区间对，只排了个总数
- 写数字写出半个人、半台机械；人员机械数跟商务册对不上
- 布置图只画一张，忽略不同施工阶段的场地变化
- 甲供、乙供材料混着写：给甲供材料也写了采购、供货安排（那不是承包商的活），
  反倒把该写的进场验收、检验、预埋安装验收漏了
- 投标文件里的材料跟招标文件的甲供 / 乙供规定冲突：把明明乙供的材料写成甲供（或反过来）、
  材料品种规格等级另写一套、漏掉乙供材料的采购报批流程
- 接口管理该单列一节却塞进别章带过，或者招标文件没要求就整个不写（白丢一个体现总承包能力的点）
- 质量那一章只写通用的三检制、报验流程，不引招标文件"专用技术要求"里的指标与检查要求
- 施组里只写"设置办公用房、会议室、试验室"这种话，不落面积、间数、数量（这些往往有硬指标）
- 临时工程的报审时限没写进方案（本次文件写几天就写几天；没提时限就不写，别照搬别处的天数）
- 程序性要求被当成"开工后的事"漏掉：施组编报时限与内容清单、招标文件指定的进度计划编制方法
  （如关键线路法 CPM）、交通组织方案要经交管部门批准
- 目标（安全 / 质量 / 工期 / 文明施工 / 环保）只挑一处抄：文件里几处说法不一致时，漏写或写低了另一处
  （质量目标这类要按高的那处写，投标人还可以承诺高于它）
- 招标文件里已经明确写出来的东西（工程重难点、工作内容、接口、材料供应、工程目标）没逐条体现 ——
  招标人写出来就是要你答的，漏一条就等于没答
- 把招标文件的"设计控制措施"当自己的对策抄（那是设计口径，评的是施工对策）

## 施组交稿前的检查清单

- [ ] 措施跟着工法改过了（没有还留着地上或桥梁那套）
- [ ] 施工方案全篇按施工顺序展开，不是按清单单位工程抄
- [ ] 招标文件已写明的重难点、危大工程逐条体现、逐条给对策（危大工程一项不少）
- [ ] 两张图齐：工程位置图 + 按施工阶段的平面布置图
