# 创新创业大赛 · 商业计划书模板生成技能

## 角色分工
- **队长** — 执行摘要、SWOT、团队信息、里程碑、风险对策
- **技术** — 产品功能、技术架构、壁垒、开发进度
- **商业** — 市场调研、TAM/SAM/SOM、竞品、收入模式、财务预测
- **设计** — 产品UI、截图美化、PPT制作
- **路演** — 路演稿、Q&A题库
- **文案** — BP润色、文档整理、附件材料

## 输出格式
- 封面（含赛道/组别/项目名/负责人/日期）
- 目录
- 八大章节（1.执行摘要 2.市场分析 3.产品方案 4.商业模式 5.运营计划 6.团队 7.财务 8.风险）
- 附录
- **Word格式**，带标题层级（H1蓝色大号/H2深灰中号），填空项带【】标签+灰色提示文字+👤角色标识

## Word文档样式规范
- 一级标题：16pt 蓝色 #2B579A（商业计划书正文风格的蓝色系）
- 二级标题：14pt 深灰
- 填空标签：【标签名】蓝色加粗
- 提示文字：灰色 #AAAAAA 10pt
- 角色标识：[角色] 橙色 #CC6600 9pt 加粗

## 成本测算口径（用户多次纠正，2026-08-13 案例：凿岩台车BP）

补 4.3 成本结构 / 4.4 盈利预测 / 7.1 营收预测时，用户逐条纠正过的口径：

1. **软件成本按软件口径算，台车造价≠软件造价**（用户两次纠正："这个台车造价，不是咱们软件造价""要分开的"）——卖的是软件，成本结构只算软件的账（人力/服务器/AI调用/标定），设备成本（台车制造成本、毛利率50%之类）是台车厂的事，写进 BP 就串台
2. **调研报告数据只作参考基数，不能作为依据**（用户原话："你可以作为参考，但是不能以此为一句依据"）——台车年产量/价格表（如国产单臂台车年产量约470台）可当"软件可服务台车基数"的量级参照，但市场规模/成本/盈利必须按软件自己的推算逻辑（保有量×渗透率×单价），渗透率/定价等假设白纸黑字标注"假设值、待团队确认"，不冒充实测
3. **AI调用成本按套累加，不能做除法摊薄**（用户两次强调："每套不是都会用ai调用吗""卖出去10套，那10套也是会产生10套的ai调用，所以这个不能做除法的"）——每套软件都在用AI，总成本=单套成本×套数（乘法累加）；单套量级极小（日常简单问答约2万token/天≈¥1/月），但口径必须是"按套"，不能把总量除以套数写"平均到每套"
4. **token 量级按正常使用算，不夸大**（用户纠正："用户只是简单的问一些问题，也不写代码不输出什么奇奇怪怪的东西，我们就正常计算就好了"）——简单问答一次500~2000 token（资料库先检索再喂，不整库发送）；本地引擎计算（爆破设计/施工日志主体模板）不走AI；单套约¥1/月、1年期约¥11、3年期约¥33；**两倍预留作预算**（覆盖波动+锁定兜底）；"锁token不影响正常使用"是成本管控亮点
5. **人力成本分开发期/维护期**（用户纠正："人力成本不用那么高，后期维护就一个人就行了"）——开发期团队N人×月薪×开发周期（一次性，周期无法测算就写"以实际项目为准，金额不单列"）；交付后维护期1人×月薪/月（维护周期随客户项目走）；不要一直按N人算
6. **定价按客户施工期**（用户思路："根据施工客户使用长短来进行更改，如果这个客户就施工一年，或者施工三年，他们的定价肯定是不一样的"）——1年期/3年期不同授权价，授权期跟着项目走；营收预测的关键假设按此写，不是固定年费
7. **定价找行业人确认 + 打包价必须低于单年累加**（2026-08-13 凿岩台车案例）：先拟"1年期6.6万、3年期20万"，被使用者发现 3年打包 20万 > 1年×3=19.8万（打包反而贵2000，使用者："很离谱"）——**打包价必须比单年累加便宜才有吸引力**；最终由设备所所长确认"行业行情基本15万/套、类似买断性质"。教训：① 定价逻辑自查（打包<累加）；② 定价数字不自己拍，找懂行情的人（对接人/所长）确认，BP 先标"初拟待确认"再回填
8. **买断制盈利测算=单客户全生命周期成本模型，不能简单"当年收入÷当年成本"对冲**（使用者明确纠正："做成本测算的话不能这样算""要按单客户全生命周期算：一套客户服务几年花多少成本，15万买断能否覆盖"）——买断是一次性收入、维护是持续性支出，拿 15万 对冲 4.1万/年 固定成本得出"卖1套就回本"是错的。正确模型：
   单客户全生命周期成本 = 开发分摊（按1套全摊最保守）+ 维护分摊（1人×月薪，服务所有客户→按同时客户数分摊）×服务年数 + 云服务器分摊 + 单客户一次性部署标定差旅 + AI调用（按套累加）
   场景表（同时服务1/3/5/8客户 × 服务1/2/3年）：3客户+服务3年≈10.3万<15万✅；5客户≈8.7万✅；**极端"全公司仅1个客户+服务3年"≈18.3万>15万⚠️**——识别风险点，用续费/升级服务对冲。结论表述：正常多客户运营下买断价覆盖全生命周期成本，仅极端场景亏损
9. **单客户一次性部署+标定+差旅按"去几人×去几天"规格算**（使用者确认口径）：2人×7天 ≈ 1.5万 = 交通0.3万（2人往返高铁）+ 住宿0.42万（2×7晚×300）+ 食补杂费0.21万（2×7天×150）+ 试爆标定0.5万（炸药/器材/现场配合）；作为单客户成本单独列，不混进人力/固定成本
10. **营收预测销量与上游设备销量挂钩**（2026-08-13 凿岩台车案例，使用者要求"把理由和公式以及数据出处都写出来"）——软件卖给设备配套，年销量不拍脑袋：
    公式：软件年销量 = 上游设备年销量 × 配套率/渗透率（全电脑台车每台必配布孔软件）；第1年 = 合作厂商设备年销台数 × 100%；第2~3年 = 行业设备总量 × 渗透率（假设值标注）。
    BP 里必须写：① 挂钩理由（每台设备配一套软件）；② 公式；③ 数据出处（调研报告具体页数，如第18/30/47页）；④ 假设标注。案例：合作厂商台车预计年销5台 → 第1年5套；行业约1100台/年×渗透率0.7%~1.4% → 第2年8套/第3年15套；收入=套数×买断价。
    市场规模同源：TAM = 设备年产量 × 软件单价（理论上限，如1100台×15万≈1.65亿/年）；SAM = TAM × 渗透率（10%~30%假设）；SOM = 首年实际套数×单价。
