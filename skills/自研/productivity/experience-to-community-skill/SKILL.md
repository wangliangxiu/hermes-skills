# 把真实经验做成技能（访谈式倒料）

## 何时用

- 社区/同事要使用者交一个「把你干过的东西做成技能」
- 使用者说「把你懂的那块做成技能」「社区让我交个技能」

## 选题三条标准（不要拿「容易被转发/传播」当标准）

1. 他真答得出来：张口能讲两三分钟、带具体场面和例子
2. 别人拿去能用：不依赖他的单位、地区、具体项目
3. 不需要写代码：纯规则 / 清单 / 句式的知识型技能

他参与社区是为爱发电，不图传播量、也不图变现——把「传播度」当选题标准会被当场驳回。

## 流程

1. 盘点经历，列出候选题目（每个说清：给谁用、解决什么、为什么通用），让他挑**一个**，别铺开
2. 访谈倒料：**一次只问一题**，他答完再问下一题（他明确选过这种「乙」方式）
   - 给两三个选项让他挑（「是 A 还是 B」）比开放题好答
   - 他说「说不上来 / 记不清」就跳过，**绝不替他编**——编了技能就废了
   - 他跑题补充别的内容时：先记下补充，下一问把没答完的问题换个问法再问
3. 逐条记素材到 `桌面\我的小项目\<项目名>\访谈素材.txt`
   - 追加**必须用 patch**；write_file 是整体覆盖，会把前面的问答全吃掉
   - 每条答完顺手提炼一句【提炼】，那就是将来 SKILL.md 的骨架
4. 他主动提「可以喂你一些真实文件」时接住：建样本文件夹，说明能读 docx/pdf、`.wps` 先另存、只看业务内容、社区版一律去名
5. 写第一版 SKILL.md：frontmatter 的 `name` 用小写连字符，`description` 头 57 字讲清「什么时候用」
6. 让他逐条改口子。他说「很多细节还没理清楚、下午带鼠标给你说」时**停手**，别抢着改
7. 装到本机实测：拿真实场景跑一遍，看像不像真干活的人写的
8. 出社区版：去掉单位名、项目名、人名、具体地名（举例子改成「××市××路口」这类通用说法）

## 他开讲、我落盘的节律（跨会话接力）

- 长项目跨好几天：开工第一件事读工作区的《进度与素材索引.txt》——里面写清技能本体在哪、素材清单、
  样本来源（含以后要重读的页码）、他讲过的口径、待办；收工时更新它。会话断了不重讲，靠它接上
- 他讲经验常是「点页 + 一句话」（例：「你在看招标文件 p192，就是按照清单来的」）：听到页码先真的
  把那几页原文抽出来看，再回话说你看到了什么，然后问「我理解你的意思是 A 还是 B」——
  他的意思常要两句才说全，先取证再落盘，别抢着下结论
- 一条经验要同时落三处：技能 SKILL.md ＋ 过程串讲稿 ＋ 《进度与素材索引》的口径清单；只落一处下次接不上
- 落盘时分清「他明确讲的」和「我推的」：推断那部分单独列出来请他核（「有一条是我顺手加的、
  不是你原话，你核一下」），他确认了才算定稿
- 他爱挂一句「这只是举例，具体标段按本次招标文件分析」——照写进去，别把举例升格成通例

## 起草 SKILL.md 的内容要求

- 开头写一条**现实约束**（例如做标只有一个月/半月/一周），技能才像真干过的
- 必须带：判断规则、检查清单、模板句式、常见坑、以及「不做什么」
- **流程不要写成一条直线**：先写分流判断（这个场景属于哪一类 → 走哪条路），他会专门指出这点
- 他的真实工作法原样保留，哪怕听着「不正经」（例：标书里「我比较懒，只找必须重写的，其余默认沿用」——这是好方法，写成核心方法）

## 出社区版：打包与发布前检查

- **先定形态：单个文件，还是文件包** —— 技能落地只有这两种。主线能压到 14k 字符以内、又没有大块清单/
  对照表/模板/脚本 → 就写成一个 SKILL.md，目录下不放别的文件；主线超 14k，或有逐条对照表、长篇清单、
  脚本、模板 → 做成文件包（SKILL.md ＋ `references/`，需要时再挂 `scripts/` / `templates/` / `assets/`）。
  定了就照那种落地，别做成「一半文件一半包」（他的原话：说白了就是单个文件或文件包那种）
- **主线别太厚**：SKILL.md 一般 8~14k 字符；涨过 20k 就按标题切段拆进 `references/` —— 切段时原文一字不动、
  只挪位置（按「以 # 开头的行」分段即可），拆前先 `cp SKILL.md SKILL.md.bak`，删掉的旧备份只留一份
- **frontmatter 按同行补齐**：除 `name`/`description`，还要 `version`/`author`/`license`/`metadata.hermes.tags`
  （校验不强制，但同行都有；`description` 控制在 1024 字符内）
- **顶部一条「数字与例子声明」**：技能里出现的数字、面积、间数、天数、时限、表名、章节号、项目名一律声明为
  举例、以本次文件为准；每个 `references/*.md` 开头放同一句。正文里每个具体数都带「举例」或「数按本次文件」——
  他会专挑数据的地方看，把举例的数当规则留下比漏写更糟
- **去私人化再过一遍**：grep 项目名/地名/人名/「使用者」/日期/页码，逐处换成通用说法（「××项目这份」→
  「同一份招标文件」）；页码、素材来源这类只留在私有《进度与素材索引》里，不进社区技能
- **打包方式先看同行**：拿不准怎么组织就盘一遍已装技能（SKILL.md 字符数分布、有没有 references/scripts、
  单文件厚写还是主线加细则），照多数派来，别自创结构
- **一个技能装了好几个阶段的任务 → 拆成技能族**（每个阶段一个技能，使用者按当前阶段只加载那一个）：
  按「这一步的产出交给下一步」切分，不按原文章节号切；原 SKILL.md 按二级标题切块时**用标题前缀匹配**，
  别用完整标题字符串（标题里常带引号、全角符号，精确匹配直接 KeyError，白跑一趟）；每块归到一个技能后补三样：
  什么时候用（写明「不适用：某某情况用另一个技能」）、这一步产什么、自己的常见坑与检查清单；
  frontmatter 用 `related_skills` 互指；拆完逐个自检再装
- 同一份细则不要在两个技能里各存一份 —— 存一处，另一处写「见 <技能名> 技能的 `references/xxx.md`」；
  拆完每个技能 `ls references/` 过一遍，清掉不属于它的（复制出来的副本以后必然漂）
- 改完/拆完**同步已装副本**（工作副本和 `~/AppData/Local/hermes/skills/<name>/` 两份），再用 `skill_view`
  确认能读出来、`references` 都挂上
- 深度做法（校验片段、切段写法、去私人化 grep 清单、声明模板）→ `references/skill-packaging-and-publish.md`

## 常见坑

- 把没做过的成果说成做过了（他会当场抓）→ 没写就说没写
- 拿「漏改 / 踩坑惨案」当亮点：先问他真发生过没有，没有就撤掉
- 例子里的真实地名、单位原样写进社区版
- 一次问三四个问题：一题一题来
- 超大 docx（百 MB 级、含大量 EMF 图纸）用 python-docx 会失败（内里关系指向 word/NULL 就报 KeyError）；
  改用 zipfile 读 `word/document.xml` + lxml iterparse，配合 `word/styles.xml` 的 styleId→name 映射提标题和正文
- 把「本次招标文件的值」当成通用规则写死（暗标、页数上限、正副本份数……）→ 他会纠正；一律标成示例
- 拿不准某项是「要去看」还是「必须写」→ 按要查项记，等他说了再升级
- 说了「已落盘」就一定要真落盘：本轮只写了一半文件却说成全部写完了，被自己发现的疏漏要当场更正；
  每轮回话先交代「文件现在有什么」，别把打算说成已做
- 批量改多个文件用 `execute_code` + `hermes_tools.patch`；中文段落里含英文双引号时别用三引号字符串收尾
  （`…内容"` 紧接 `"""` 会提前闭合三引号 → SyntaxError），改用单引号字符串 + `\n` 的隐式拼接
- 读样本用的临时脚本写进 `$LOCALAPPDATA/Temp`、用完当场删掉，不落桌面
- 拆分时目标技能名跟源文件夹同名 → 直接写回源目录，把源文件覆盖掉（还会报 SameFileError）；动手前先确认
  源与目标不是同一个目录，或先把源挪到临时目录再写
- 清理旧文件用 `rm -rf` 会被拦下等人确认（无人在场就一直卡着不返回）→ 用 `mv` 挪到临时目录：可逆，且不触发确认
- `patch` 改 frontmatter 时新旧字符串容易不一致 —— old 带着结尾那行 `---`、new 忘了写，技能就校验不过。
  动过 frontmatter 一律重验：首字节是 `---`、`\n---\n` 能闭合、YAML 能解析、`name`/`description` 在、
  正文非空、全文 ≤10 万字符
- 把「举例子」的数留在技能里当通用要求（他的纠正：「小细节只是举例子，不是完全要求这样」；
  「所有牵扯到数据的地方都要注意」）→ 每个具体数要么明确标「举例」，要么干脆不写数、写成「数按本次文件原文」
