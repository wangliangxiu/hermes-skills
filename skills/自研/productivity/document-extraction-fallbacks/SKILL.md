# 文档提取的退路（PDF / .docx / .doc）与表格格式量取

## 什么时候用它

- 标准提取器打不开文件或提取不出文字：`python-docx` 报关系错误（如 `word/NULL`）、老格式 `.doc`、
  提取结果里混进整份目录、或取出来的是空字符串
- 输入是一张**很高的截图 / 长图**（视频总结长图、公众号长图、聊天记录长图），没有文字层，整张丢给识图工具只会拿到一堆糊字 —— 见第六节
- 需要**照抄某张表的格式**（列、表头分格、行高列宽、缩进），不能靠肉眼猜
- 常规 PDF / 扫描件 / OCR 场景先看 `ocr-and-documents`（bundled）：本技能只补它没覆盖的退路

## 一、docx 打不开：改读压缩包里的 XML

`python-docx` 会遍历包内所有部件，遇到坏关系（`word/NULL` 之类）直接崩，与文件大小无关。
退路是把它当普通 zip 读：

```python
import zipfile, re
xml = zipfile.ZipFile(path).read('word/document.xml').decode('utf-8', errors='replace')
for p in xml.split('</w:p>'):                      # 一段一个 <w:p>
    txt = ''.join(re.findall(r'<w:t[^>]*>(.*?)</w:t>', p, flags=re.S))
    txt = re.sub(r'<[^>]+>', '', txt).strip()
    if txt:
        print(('【粗】' if '<w:b/>' in p or '<w:b ' in p else '') + txt)
```

- 只解析 XML，不碰图片，几百 MB、上千页带图的 docx 也读得动
- 文件正被 Word 打开（同目录有 `~$xxx.docx` 锁文件）不影响读

## 二、按章取正文：先滤掉目录

目录段的文字与正文标题完全相同，直接按标题搜索会先命中整份目录。
判据：**段里含 `PAGEREF _Toc` 的就是目录**，在遍历时跳过。
另外先读书签目录（PDF `doc.get_toc()`）拿章节页码，再只取要用的那几章 —— 别把几百页整本灌进上下文。

## 三、老 .doc（Word 97-2003）

用 `antiword`（中文正常显示）：

```bash
antiword 文件.doc > /tmp/out.txt      # 整本转文本，之后在 out.txt 里检索章节
```

- 表格会被拍平成纯文本；需要表格结构就找同内容的 PDF / xlsx
- 磁盘上同名的 `.docx` 与 `.doc` 混放时，先看文件头（`xxd -l 8 file`）：`d0cf11e0` 是老 .doc，
  `504b` 是 zip 型 docx

## 四、扫描件 / 拍照件

先判断有没有文字层：抽一页 `page.get_text()`，空的就是图。没有文字层才上 OCR：
`winget install tesseract-ocr`（或装 UB-Mannheim 的 tesseract Windows 版），再配 `pytesseract`；
要更强版面 / 公式能力用 `ocr-and-documents` 里的 marker-pdf。

## 五、量表格格式（照抄用）

```bash
python scripts/table_spec.py <pdf> <页号> [表序号]
```

输出行列网格、每格跨几列跨几行、列宽行高（pt 与 mm）、表格外框，以及表外文字行（"注 / 说明 / 备注"）
距表格左边缘的距离（÷ 字号 ≈ 首行缩进几个字符）。要点：

- `page.find_tables()` 的 `extract()` 里 **`None` 表示被合并 / 续格** —— 靠它可以还原"某格横跨 3 列、纵跨 2 行"
- 合并单元格式的行高要用边界坐标算（相邻 y 边界之差），不能只看文本行数
- 表外那行小字的位置也必须量：它常是填表口径，缩进与位置都要照抄

## 六、超长截图 / 长图（没有文字层的整张图）

1. **先量尺寸再动手**：`PIL` 读 `im.size`，按高度算出要切几段。整张直接送识图工具会被按高度降采样，正文完全认不出。
2. **按 region 切横条**：一次读一条，高度 ≤900px、宽度保持原宽（识图可读窗口约 622px×900px，再高就被压）。**优先用识图工具自带的 `region` 参数直接传原图坐标**，不必先用 PIL 落盘切片——少一批临时 PNG，也少一次坐标换算。从 y=0 递推，相邻条留 40-100px 重叠，防止一句话被拦腰切断。
3. **读一段、立刻落盘一段**：识图结果不会留在后面几步的上下文里，读完下一段就可能看不到上一段。每读完一条就把誊写**追加**到临时笔记文件（`patch` 追加；`write_file` 是整体覆盖，会吃掉前面读的段），最后从笔记文件汇总成答案。
4. **某条返回不出文字就原样重发一次**，指令写成「逐字誊写这一段（含表格数字）」比「描述一下」稳；重发通常就出来了。批量连发时更容易漏读，允许一条条补。
5. **表格让识图工具逐格誊写**（列名 | 数字），不要只问"这一段讲了什么"。

切片脚本、逐段推进顺序、以及"这张长图是怎么做出来的"的判定与标准生产流程，见 `references/long-image.md`。

## 常见坑

- 把整份目录当正文，改半天改的是目录 —— 先按 `PAGEREF _Toc` 滤掉
- 因为 `python-docx` 报错就断言"文件损坏、读不了" —— 崩的是包遍历，读 `document.xml` 就好
- 抄表时漏掉表头单元方式的**合并方式**（跨几列几行），只抄了文字
- 表外那行"注 / 说明 / 备注"没量缩进，抄出来位置与原文件不同
- 提取脚本写到项目文件夹里 —— 写到临时目录，用完删
- 量出来的尺寸与文件里读出来的文字混着记 —— 实测的标"实测"，与原文分开记
- 把整张长图一次丢给识图工具 —— 降采样后字全糊；超长图必须按 region 分段读
- 分段读长图却不落盘 —— 读到后面忘了前面，只能重读；每段读完立刻追加到临时笔记文件
- 把长图里的错字、病句顺手改通顺 —— 这些错字正是判断"内容是自动转写来的"的判据，照实录
