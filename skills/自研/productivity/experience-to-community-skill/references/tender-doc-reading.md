# 标书文件（招标文件 / 投标文件）怎么读、怎么提

材料通常是：一份几百页的招标文件 PDF + 一份几百页的投标施组 docx（含大量 EMF 图纸，上百 MB）。

## 先知道东西上哪儿找（信息来源地图）

写标要用的东西，先按这张表落实“在本次文件里的哪一处”——答不出就是还没扫到。

| 要找什么 | 去哪找 |
|---|---|
| 项目/标段划分/地点/规模/招标范围/估算价/总工期/评标方法 | 第一章 招标公告（整份文件的索引页） |
| 资格要求、分包、澄清截止、份数册数装订、页数、暗标、保证金、递交与开标 | 第二章 投标人须知（含前附表与附件） |
| 分值构成、“评分标准”那一列（＝内容要求）、废标条款 | 第三章 评标办法（前附表+评分表+评审工作表） |
| 质量等级、工期违约、奖罚、材料与价格约定、奖优 | 第四章 合同条款（通用+专用+合同附件） |
| 要干哪些活、施工顺序 | 第五章 工程量清单（表-08 类开项汇总去重）+ 末尾《项目及计算规则》附表 |
| 位置、控制因素、风险源、尺寸、**地质与水文** | 第六章 图纸；地质资料见下 |
| 技术标准、材料与工艺、重难点、工作内容、接口、材料供应、目标、危大工程 | 第七章 技术标准和要求（整章扫到底） |
| 施组要写什么、各类表格格式、响应偏离表 | 第八章 投标文件格式 |
| 各标段总工期与分阶段工期、节点日期 | 第二章附件 / 第七章“工程目标” |
| 施组章节骨架（铁路标） | 指导性施组（随文件下发时）—— 章节照它搭，评分也拿它对标 |

正文之外**另找的四处，最容易被漏**：①图纸册（招标文件“图纸”章常只写“另册”，先看图纸目录 xlsx）；
②地质与水文资料（见下）；③补遗书/补遗答疑（与招标文件同等效力，常改工期改条款改格式，必须逐份看）；
④清单与造价表（单价、指导单价、造价构成）。

### 地质与水文资料有两种给法，两种都得找

1. **单独出勘察报告**：夹在图纸册里，往往单独一册、**按工点再分册**（每个车站一册、每个区间一册、
   停车场一册）；每册＝主报告 + CK 系列附件（勘探点一览表、工程地质断面图、物理力学指标统计表、
   分层土工/岩石试验、静力触探、标准贯入及**液化判别与液化指数**、动力触探、钻孔柱状图、三轴、
   高压/综合固结、**水质与土壤化学分析**、电阻率、波速、旁压等）
2. **没有单独报告**（大部分是这种）：地质、地层的描述就写在**图纸文件最前面的“设计说明 / 总说明”**里 ——
   先翻图纸册开头那几页，再翻后面找有没有单册报告

报告里要提的四样（其余留给方案章）：**标准土层层序**（层号/土名/状态/密实度/成因/代号）、
**工程地质层分布特征表**（时代成因/层号/地层名称/状态/特征描述/分布范围）、
**水文地质条件**（先分地表水与地下水，地下水再分孔隙水与其他水层，再看腐蚀性、渗透性、抗浮设计水位）、
**岩土层工程地质评价表**（层号/岩土名称/状态/强度变形特征及渗透性/工程地质性能）。
这四样是拿去支撑“地基均匀性评价 + 不良地质作用及特殊性岩土（液化土/填土/软土/混合土/膨胀土/风化岩）”
两个结论的，**再拿结论去定施工工艺**（钻孔灌注桩还是套管成桩还是成品桩；现浇还是锤击/静压沉桩；
围护形式、降水与止水、盾构选型）——地质资料是为“定工艺”服务的，不是抄一段描述摆在那儿。

施组里地质那节是**摘取、不是全抄**，摘多少看本次篇幅要求：通常只有“地形地貌两三句 +
一张工程地质层分布特征表 + 水文地质一段”；不良地质与液化放重难点章，桩型与降水放方案章，
承压水/暗浜/孤石放风险源章。

## 提什么

1. **结构**：真实目录 = 文档里 `toc 1/2/3` 样式的段落（自动目录域生成），不是 heading 段落。
   正文 heading 可以比目录深——宁扬正文到五级（形如 2.3.2.1.1），目录只呈现三级
   （三级目录是为了专家评审看得清，属常规做法、非硬性规定）
2. **格式**：`word/styles.xml` 的样式定义 + 各 `sectPr` 的页面设置。正文样式常挂在 Normal 上
   （例：仿宋_GB2312 小四、行距 1.5 倍、首行缩进 2 字符、两端对齐；页边距 1417 twips ≈ 2.5cm）。
   **标题样式常常不写自己的字体字号，靠 basedOn 继承正文样式**——查格式必须顺 basedOn 链看
3. **篇幅配比**：章的页码区间能看出哪一章最厚（方案章通常占全书近一半），后面排工期和分配精力都靠它。
   **前头带过、后面写透**：工程概况与地质那节一笔带过，篇幅砸在重难点与对策、主要施工方案、
   质量/安全/风险这些重点章
4. **属性**：`docProps/core.xml` 的 creator / lastModifiedBy 会留着真人名——暗标项目这是必须清的反例
5. **页眉页脚**：`word/header*.xml` / `footer*.xml`，常年是空或只放页码域
6. **PDF**：`fitz` 的 `doc.get_toc()` 直接给书签目录（448 页的招标文件给了 623 条书签），一点就定位到章；
   逐页 `get_text()` 的字符数能一眼找出手写/扫描页
7. **表头的分格结构**（要照抄格式时）：`page.find_tables()` 拿网格，用 `cells` 里各 bbox 的 x/y 边界
   排序去重，相邻差值就是列宽/行高（pt × 0.3528 = mm）；`extract()` 里的 `None` 表示该格被左/上格合并占据；
   某行文字的 x0 减去表左边缘再除以字号，就是它缩进几个字

## 坑

- 不要用 python-docx 打开这类百 MB 标书（关系项指向不存在的部件就 KeyError）；直接 zipfile + lxml 更稳更快。
  真要走 zipfile：**必须跳过含 `PAGEREF _Toc` 的段落**，那是目录行；不跳的话按关键词命中，
  第一处永远是目录，不是正文（真拿目录当正文回话就错了）
- **几百 MB 的老格式 `.doc`（OLE 二进制）用 `antiword <file>`**，中文正常、不用先转格式；输出重定向到临时文件再分段看
- **PDF 先探有没有文字层**：取一页 `get_text()`，为空（或只剩页码）就是扫描件 → 要 OCR；
  OCR 引擎没装时别硬试，先问用户要不要装。盖章版不算扫描件（印章是叠上去的图，文字层还在）
- **别把 element 序列化出来看**：`etree.tostring()` 出来先是几百字符的 xmlns 声明，把有效信息全挤没了；
  要看格式就取 `pPr`/`rPr` 的子元素 tag+属性，或直接读 styles.xml
- 表格是这类文件的重头（评分表、资历表、工区划分表、重难点表全在表格里）；表格文字同样在 `w:t` 里，
  按段落迭代不会丢内容，保留段落顺序即可
- 大文件别一次性塞进上下文：先按页/按章切分写成 txt（每页加 `===== PAGE n =====` 标记），再按需读区间
- 统计类结论（页数、字数、标题各级条数、岗位数）一律用代码数，不靠眼看、不靠记

## 对照产物的写法（他要的形状）

一条一段：招标文件怎么提要求（带条款号、页码）→ 施组里的落点（章节号 + 实际写法）→ 概念对应 → 要点与坑。
示例值标注「本次 / 宁扬这次」，自己推断的标注「未经确认」。追加内容一律用 patch（write_file 会整体覆盖）。

可跑的脚本：`scripts/extract_docx_structure.py`（docx 概览/目录/抽章/找词组）、
`scripts/extract_pdf_outline.py`（PDF 概览/书签/抽页/找词）。
