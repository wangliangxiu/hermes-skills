# 把 Hermes 打包成客户可安装的产品：许可与安装事实

用途：要把 Hermes（或其他开源 agent）当交付底座装到客户机器上、做成「安装包」卖之前，先看这一份。**许可条款与安装方式会变，落地前以仓库 LICENSE 原文与官方安装文档为准。**

## 一、许可：MIT（可以打包、可以卖）

核实方式：看仓库根目录的 LICENSE 文件原文，不看二手转述。

关键条款含义：

- 允许：使用、复制、修改、合并、发布、**再授权（sublicense）、出售**该软件及其副本。→ 「打包装到客户机器上收客户的钱」合法。
- 唯一硬性义务：**分发时保留版权声明与许可文本**（包里放一份 LICENSE / 版权声明文件，不能省）。
- 免责：软件按 AS IS 提供，无任何担保。→ 对客户**不能承诺**「永不故障 / 永久可用」，这条与合同边界是同一件事。

衍生注意：

- 包里若含第三方技能 / 组件，各有各的许可，要逐个看；**自己写的技能版权归自己**，可以自行定授权与收费规则。
- 交付物是被许可方的软件 + 自己的资产（技能包、模板、配置），合同里把两者分开写。

## 二、依赖：官方安装器已经解决，不要自己攒

官方 Windows 安装路径（二选一）：

- 命令行：PowerShell 里跑官方 `install.ps1` 一行命令（`iex (irm …)` 形式，BOM 问题最少）。
- 桌面安装器：一个 GUI `.exe`，双击安装；官方文档明确说这套适合**把 Hermes 交给非开发者**——正是散户客户的情况。

安装器实际会做的事（重点：不用你塞 Python）：

- 引导 `uv` → 装 Python → 装 Node → 装便携版 Git（约 45MB，已有 git 则复用，不干扰系统 git）→ 配 ripgrep、ffmpeg。
- 全部装到用户目录（Windows：`%LOCALAPPDATA%\hermes`），**不需要管理员权限**，与客户机器上已有软件互不干扰。
- 安装脚本有参数可跳过首次配置向导、指定数据目录与代码目录、指定分支/标签/提交——批量部署时用得上。

结论：**产品 = 官方安装器之上那一层**（技能包 + 预置配置 + 向导 + 手册 + LICENSE），不是自己重做一遍运行环境。

客户侧预告（网络差的客户要提前说）：首次安装要联网拉依赖，体积按百兆到 GB 级估；分发方式（网盘等）提前定。

## 三、产品包构成（清单）

1. 官方安装器（原样使用，不改）
2. 自己的技能包（内容/业务流程）
3. 预置配置（默认模型与参数、目录结构、默认技能开关）
4. 首次运行向导（填 API key、行业方向、平台 → 生成个性化配置）
5. 图文操作手册 + 演示脚本（你能照着讲，客户能照着用）
6. 版权声明 / LICENSE 文件（MIT 那条硬性义务）

## 四、安装包外壳

- Windows 上优先 **Inno Setup**（免费、生成单个 `.exe`、向导式界面），学习成本低。
- 顺序：先用脚本 + 技能包把流程跑通并能演示，再套外壳做正式安装程序——先做界面是浪费。

## 五、IP 暴露与更新分发

- 技能包装到客户机器上后，客户能直接看到提示词与模板（=核心资产）。交付前明确：授权范围、署名、是否允许转卖/教学。
- 对策（按强度递增）：更新分发制（只在更新里迭代真正的核心）→ 激活码/授权校验 → 把最关键的调优留在自己服务侧。
- 更新包本身就是续费载体：同一份更新发给 N 个客户成本相同，这是这门生意唯一的复利来源。
