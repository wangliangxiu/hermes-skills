# 标书样本拆解（提炼标准模板）

触发：用户说"以某份标书作为标准模板""把样本标书拆开看看""素材库盘一遍"，
或要为投标技能族（bid-tender-scan 检查招标文件 / bid-document-writing 编写投标文件 /
bid-technical-proposal 编写施工组织设计）产出通用骨架与格式规范素材。

## 铁律

- 只读样本，原文件一个字都不改。
- 中间脚本放 $LOCALAPPDATA/Temp，跑完即删；不在桌面和项目文件夹留脚本。
- 提炼产物一律 txt（用户不看 md），落到 `我的小项目\Hermes社区技能\样本标书\`。
- 用户自己写的技能文件（桌面项目文件夹里的 SKILL.md）只有他说"改技能"才动；他没发话就先出草稿等他定。
- 长命令（几十秒以上）开跑前说一句在跑什么，跑完报结果。
- 往已有素材文件里加内容用 patch，不要 write_file 整体覆盖（会把前面记的内容吃掉）。
- 分清【要查项】和【必有项】：用户说"要注意"的都是**去查、去看**的点，只记"看什么、在哪看、找到之后落到哪"，不是要求；什么样的内容"一定要有"由用户明确给出，不自作认定，自己推出来的判断一律标注"未经确认"。把某一份招标文件里的具体值（暗标、页数上限、字体、目录层级、有没有否决条款）写成通用规则的，用户一定会纠正。
- 样本里读出来的做法标成"样本如此"，拿不准的列成"待用户拍板"，不要写成结论。
- 说"已落盘/已保存"之前必须看到写入工具的成功返回；没执行就报完成，用户会照着不存在的文件干活。
- 用户说"先听我说完""先别动"就立刻停手，别边听边改文件或技能。

## 两条底层逻辑（用户定的，压在所有条目之上）

1. **内容一定要满足招标文件** —— 招标文件怎么要求就怎么写，实际情况（比如工人其实是外包的）不改变"答什么"，
   只影响怎么把答案写圆：要求自有工人占比，就把自有工人比率写上。
2. **数字要符合实际、经得起推** —— 不能出现半个人、半台机械。按工区/工序拆分拆出小数时：总量还能加就往上取整、
   多写一个（2.5 → 3）；总量已经定死就在工区之间按工作量调剂（工作量小的 2、大的 3，加总等于定死的总量）。
   前提都是不违反招标文件（它给了上限或硬性规定就不能乱加）。

## 收尾产出：核查提醒（每次核完都给一份）

三类写清，不要只丢结论、也不要只报问题：① 已核查、没问题；② 已核查、但拿不准；③ 智能提醒（核不了、要人做的）。
能自己核的当场核：暗标（公司名、人名、其他项目名、徽标、文档属性）、技术标里是否出现报价数额、联合体（协议书与牵头人）、
章节与招标要求是否一致、工期是否超限、位置图与布置图是否齐。
核不了的列成提醒：盖章、签字、骑缝、装订、密封、份数、平台上传与现场递交。
这类检查写成流程和提醒格式就够 —— 用户明确说过不要为此做脚本。

## 工作流

1. 定位与探查：确认路径存在、看文件大小。100MB 级 docx 里通常塞满 EMF 图纸（单张 1~3MB），不要整体加载。
2. 一遍提取（docx 样本）：跑 `scripts/extract_docx_outline.py <file.docx> <out.txt>`，一次拿到文档属性（Pages/Words）、页面设置、样式表、目录（toc1/2/3）、标题层级计数、表格与图形数量、页眉页脚。
2b. 按章取正文：`scripts/extract_docx_chapter.py <file.docx> <起章关键词> <止章关键词> <out.txt>`，只落需要的章，别把整本书读进上下文。
2c. 招标文件（通常是几百页 PDF）：`scripts/extract_pdf_outline.py info|dump|find <file.pdf>`，先用内置书签定位章节页码，再只把那几页落盘。关键节固定在那几处，见 references/tender-to-proposal-mapping.md。
3. 汇报三件事：体量与结构（多少页、几章、附表附图各几张）、章节骨架、排版格式（页面 / 正文 / 各级标题 / 页脚页码）。
4. 落素材：把骨架（带页码）+ 格式规范 + 篇幅配比写成一份 txt，放进样本标书目录。
4b. 招标文件与样本配套时，做"招标文件 → 施组"的概念对照：一条评分点一段，每段按「招标文件原话 → 施组里的落点 → 概念对应关系 → 要点与坑」写，落成 `投标施组逐条对照_<项目>.txt`。做完一条就汇报、等用户确认再下一条——他是"一条一条来"的节奏，别一口气推完。
5. 去项目化：要进社区技能就抹掉项目名、站名、单位名，只留方法与判断。
6. 直说选型判断：样本强在哪儿（结构齐、图多、篇幅敢写）、弱在哪儿（不对应评标办法、个别章天然不能套），不要一味夸。
7. 一条口径落三处，会话断了也能接：① 技能本体 SKILL.md（分类规则、清单）② 逐条串讲稿 txt（用户口述的原话与例子）③ 进度与素材索引 txt（技能路径、素材清单、样本页码、已定口径、待办）。新开一场先读索引再动嘴，不要让用户重讲一遍；索引里注明"谁什么时候定的口径"，方便以后分清哪些是用户拍板的、哪些是样本读出来的。
   用户讲经验时是**一条一条喂**：讲完一条就落盘那一条，再等下一句；他插话纠正上一条时，先把技能里写错的那句改掉（别在下面追加"其实不是……"），再往下走。

## 提取脚本

`scripts/extract_docx_outline.py <file.docx> [out.txt]` —— 只依赖 zipfile + lxml，无第三方依赖。

## 坑

- 这类投标 docx 常带坏的关系项，python-docx 打开会抛 `KeyError: "There is no item named 'word/NULL'"`。别去修 docx，直接 zipfile + lxml 读 `word/document.xml`、`word/styles.xml`。
- 标题不要凭"看着像标题"判断：读段落的 `pPr/pStyle` 拿 styleId，再用 styles.xml 的 styleId→name 映射还原成 heading 1..6 / toc 1..3。
- 标题的实际字体字号常靠样式继承（run 级没有 rPr，看起来"没格式"），要顺着 `basedOn` 链看；正文样式本身（如仿宋_GB2312、小四）就是答案。
- 目录层级 ≠ 正文层级：目录一般呈现到三级，为的是让专家评审看得清——这是常规做法、不是硬性规定，招标文件另有要求按招标文件；正文标题可以做到四级、五级。别把样本的层数当规则讲给用户（用户会纠正）。
- twips 换算：字号半点制（24 = 12pt = 小四）；页面 twips/20 = pt，/567 = cm。
- 目录文本尾部的数字是 Word 域记录的页码；按结尾连续 1~3 位数字剥离即可，但标题自带数字时要留意误判。
- 暗标项目顺手看一眼 `docProps/core.xml` 的 creator / lastModifiedBy——这是现成的必清项反例。
- 大文件里的 EMF 图纸是内容主体，提取时只统计数量，别试图转换。
- 招标文件 PDF 往往带几百条内置书签：先 `get_toc()` 定位章节页码再只读那几页，整本灌进上下文是纯浪费。
- PDF 里文本量极低的页多是扫描图或空白表格页（投标文件格式部分常见），不是提取失败，别反复重试。
- bash 里给原生 python 传 MSYS 路径（`/f/...`）会报找不到文件：传 `F:/...` 或 `F:\...` 原生路径。
- 多行逻辑写成 .py 文件再跑，别用 `python -c`（引号转义费劲，出错也难查）。
- 是被"一条一条来"的节奏喂料的：做完一条就汇报、等确认，别一口气把后面几条也推完；用户中途插话时，他讲的那条往往比手上的活更要紧。
- 被问"某某岗位/术语是什么"时，先到招标文件全文里搜一遍再答（同一角色常有多处不同叫法，例：安全质量管理负责人／安全副经理／安全总监／项目安全负责人指同一个岗）。
- 同类判断下次还要用的，落进 references/ 而不是只写在对话里；但"必有项"这类必须由用户拍板的东西，标成待确认别写成规则。
- 同一个要求招标文件里常写好几遍（合同条款、第七章技术标准和要求、第八章投标文件格式各一遍，措辞有出入）：定关键词全文搜一遍，把每处出现的位置与原话列出来比对——一致就照写一遍，**不一致就都写上（取并集、取大值，一处不丢）**；同一件材料前后用词不同（"预埋套管"与"预埋套筒"）即使判断是一回事，也要在问题报告里点出来让编标人员关注，别自己闷头判一个口径。对外发问走第二章澄清程序、注意澄清截止日期。
- 判断"对上了没有"要量化，别靠肉眼看着像：列宽、行高、表头每格跨几列×跨几行、小字与注的缩进量，都能从 PDF 里量出来。跑 `scripts/measure_pdf_fmt.py <file.pdf> <页>` 拿数（表头合并靠 extract() 里的 None 续接标记推，缩进＝(该行 x0 − 基准 x0) ÷ 字号 得几个字符）。照抄格式类内容时，动手前先量一遍，报数给用户对。
- 格式类内容照搬的是**本次这份文件**，不是固定套路（有几张表、有没有这些表，都按本次文件）：能被自己动的只有表格里的行数，其余一律不改——列、列名、表头分格与行高、单位与大小写（文件写 Kw/m3 就照写，别改成 kW/m³）、表格外左上或右上角那行小字、表后跟着的注/说明/备注及其位置与缩进。改动了就不叫按格式要求编制。
- 招标文件里明确写着数量的硬要求（如逐区间写明的盾构机台数）别照着想象往施组里填：进提醒清单，让编标人员去找机械部门或设备厂家核实台数、机型、到场时间、自有还是租赁——承诺的机械到场时间不满足工期，有的文件直接算无效标。
- 正文里 `**` / `***` 打码的参数（管片外径、管片厚度、强度等级、桩径这类）不是"文件没写"：第五章末尾写着"工程量清单详见招标文件的其他材料部分"，去那份清单 PDF 的"项目特征描述"列读实数，图纸更全；两处都没有就把这一项列进问题报告。
- 同类设备的明细表要做几张，看**类型**不看台数：同类型合并成一张表，类型不同才各做一张——一台一张、一个工区一张都不对。
