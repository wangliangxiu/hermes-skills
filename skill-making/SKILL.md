# 把一套经验做成技能（打包与安装）

## 什么时候用它

- 用户说：做成技能、把方法存成技能、写个技能、这套流程以后还用得上
- 手上已经有一套经验 / 流程 / 实录（访谈记录、旧标、踩坑笔记、工作习惯），要变成能反复调用的技能

不管这些：怎么把经验从人嘴里问出来（那属于经验访谈类技能）；往 hermes-agent 源码仓库里提交技能
（那有专门的 in-repo 技能写作技能）。这个技能只管**做成文件、控大小、去私人化、装上去、保持同步**。

## 先定形态：做成单个文件，还是做成文件包

技能落地就这两种，动手前先定下来：

- **单个文件**：内容全写在 SKILL.md 里，技能目录下不放别的文件。
  适合：主线能压到 14k 字符以内、没有大块清单 / 对照表 / 模板 / 脚本的技能。
  好处：一个好读好拷好交；代价：内容多了就摊大饼。
- **文件包**：一个文件夹，里面 SKILL.md（主线：什么时候用、流程步骤、检查清单、常见坑、不做什么）
  ＋ references/（细则，一个主题一个文件）；需要时再挂 scripts/（脚本）、templates/（模板）、
  assets/（图、样例）。
  适合：细则多、清单长、带脚本或模板的技能。
  好处：主线永远短，细则用到才读；代价：要维护同步。

怎么定（按内容量定，不按喜好定）：

- 主线能压到 14k 字符以内、又没有大块附表 → 单文件
- 主线超 14k 字符，或有逐条对照表 / 长篇清单 / 脚本 / 模板 → 文件包

定了就照那种落地，别做成"一半文件一半包"。

## 硬规矩（先记住这几个数）

- 描述（description）≤ 1024 字符；单个 SKILL.md ≤ 100,000 字符 —— 超了校验不过
- 同行普遍 8~14k 字符；**超过 20k 就该拆 references**
- frontmatter 除 `name` / `description`，还要 `version` / `author` / `license` / `metadata.hermes.tags`
  （不强制校验，但同行都有，缺了看着像半成品）
- 文件 UTF-8；frontmatter 第 0 字节就是 `---`，结尾要有单独一行 `---`，之后正文非空
- 描述以触发条件开头（"当……时使用"），别把正文内容抄进描述

## 第 0 步 先盘同行，别凭空造结构

跑一次清点脚本（这个技能自带 `scripts/survey_peer_skills.py`）：列出每个技能 SKILL.md 的字符数、行数、
支持目录（references/ scripts/ templates/），看中位数落在哪、厚的那些是怎么拆的；再挑 2~3 个同类技能，
看它们的头部 20 行和 references 目录列表。

据清点结果定结构：

- 必须"每次都要知道"的只有流程与检查清单 → **主线 SKILL.md + references/**
- 全是短流程、没有长清单 → 单文件写完也行（同行里也有 3 万字符的单文件）
- 判定标准：主线超 14k 字符，就把细则、示例、长篇清单、逐条对照表赶进 references

## 第 1 步 先在工作副本里写，不直接改已装目录

- 工作副本放项目文件夹（例：桌面\我的小项目\<项目名>\<skill-name>\），跟用户一起打磨的就是它
- 一条规则一句话，可执行、带条件、带完成判据；不要写"要认真""注意质量"这类不改行为的空话
- **用户的原话照记**，不自作主张改口径；拿不准就当场问
- 凡是数字、面积、天数、表名、章节号、项目名 —— 一律写明"**只是举例，按实际情况**"

## 第 2 步 拆 references

- 一个主题一个文件，中文文件名可以（`references/材料怎么写_甲供与乙供.md`）
- SKILL.md 末尾列一份"细则文件（references/）"，每条一句"什么时候读它"
- 正文里交叉引用写相对路径：见 references/xxx.md
- 规模参考：SKILL.md 8~14k 字符；单个 references 1~15k 字符
- 大块资产（表格模板、脚本、样例）分别放 templates/ scripts/ assets/

## 第 3 步 自检（缺一项都别装）

1. **frontmatter**：起止 `---` 都在、YAML 能解析、`name`/`description` 在、描述 ≤1024、全文 ≤100000、正文非空
2. **脱敏（做的时候就做，不要等要公开了才补）**：默认按「这份技能会公开」来写，写完 grep 一遍。要清的：
   - **真人姓名** → 用「王工 / 穆工 / 徐工」这类代称（同事、领导、客户、亲属一律化名）
   - **电话、邮箱**（尤其 QQ/163 这类私人邮箱）、身份证、住址
   - **私人会话与日志**：`session-*.md`、teaching/learning log、聊天记录原文、访谈原话、
     项目内部进展记录 —— 技能只留方法与模板，具体会话内容一律不进技能
   - **真人人物画像 / 人物蒸馏示例**（`example_<人名>`）—— 放合成示例，不放真人
   - 项目名、公司名、页码、日期 → 模糊成「某份招标文件」「某项目」
   自查命令：`grep -rniE "1[3-9][0-9]{9}|@(qq|163|126|sina)\\.com|session-|聊天记录|访谈原话" <技能目录>`
   命中即处理。页码这类只留在私下的素材/索引里，不进技能
3. **数字与举例**：牵扯数据的地方都写明"举例"
4. **结构完整**：什么时候用 / 流程步骤 / 常见坑 / 验证清单 / 不做什么

## 第 4 步 安装 + 验证 + 同步

- 拷进技能目录：`cp -r <工作副本> "$HOME/AppData/Local/hermes/skills/"`
- 验证：`skill_view(name='<技能名>')` 能读出正文，且 `linked_files` 里挂着 references
- **两边会漂**：以后改流程一律改工作副本 → 再 `cp` 覆盖已装副本；改完不拷，下次调用用的还是旧内容
- 另有桌面版 hermes 的技能目录（本机是 `D:/a2e-skills`），要装那边先说一声再装

## 第 5 步 维护

- 新学到的东西补进对应文件（该进 references 就进 references），别一层层往主线叠
- 技能应该越改越短越准：加一条规则时，顺手删掉它替代的旧说法
- 只留最新版：旧版别在工作副本里堆着（要留就挪到临时目录）

## 技能改了要回归产物（铁律）

技能不是改完就算了：凡是**已经用它做出来过东西**的技能，改完必须回头把那些产物按新技能重新生成一遍，
然后重新分发（覆盖旧压缩包、重新上传仓库）——否则技能和产物两份不一致，下次用哪个都可能出错。

顺序：改技能 → 重出产物（含验证：看图 / 跑测试 / 数字复算）→ 重新打包 → 仓库覆盖旧版。
反例：修了「公式里不能夹汉字」这条坑，却只改技能不重排已交的卷子，那卷子里照样有方框。

## 常见坑

- **补 frontmatter 时把结尾那行 `---` 吃掉** → 校验不过、技能读不出来；改完必须重跑第 3 步自检
- 只改已装副本 → 工作副本反而旧了；只改工作副本 → 调用的还是旧的。两边都要拷
- SKILL.md 冲到 2 万字符还不拆 references（常见的摊大饼）
- 把用户的举例当规则写进去（面积、天数、表名、章节号）→ 必须写成"举例，按实际情况"
- 交出去前没 grep，留了项目名、人名、页码、日期
- 想指定写入位置却用 `skill_manage(action='create')` → 它只写用户技能目录；要指定位置就 `write_file` / `cp`
- 临时脚本写到桌面 → 用 `$LOCALAPPDATA/Temp`，用完删

## 验证清单

- [ ] frontmatter 起止 `---` 齐、YAML 可解析、描述 ≤1024、全文 ≤100000
- [ ] SKILL.md 落在 8~14k 字符（超 20k 的已拆到 references）
- [ ] references 每条都写了"什么时候读"
- [ ] 脱敏自查命令跑过（电话/邮箱/session-/聊天记录/访谈原话/真人姓名），无私人信息
- [ ] 所有数字、表名、章节号都写明"举例"
- [ ] 已拷进 `$HOME/AppData/Local/hermes/skills/`，`skill_view` 能读出且 references 挂上
- [ ] 工作副本与已装副本内容一致（diff 无差异）
