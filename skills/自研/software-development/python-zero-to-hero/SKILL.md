## 讲解风格
- **优先用代码语言解释**（逐行对照程序原文），而非用力过猛的类比
  - 使用者两次确认这个偏好：「对照着程序语言讲」
  - 先讲这行代码做了什么、变量/参数分别是什么值，类比作为补充手段而非主要方式
  - 示例：讲 `for r in records:` 时，先说 `r` 是临时变量在每轮循环被赋值为列表中的元素，再说`len(records)` 是数列表长度，最后再用类比强化
  - 误区：不要一上来就「就像一叠发票一张张翻」— 使用者觉得类比绕，更喜欢「第1轮 r=xxx，第2轮 r=yyy」这种程序逻辑描述
  - 当使用者说「没太明白」时，**先直接逐行对照代码再讲一遍**，不要先问要不要换比喻——使用者可能只是没完全对上，而不是想换方式
- **使用者说「对照着程序语言讲」意味着：逐行列出每行代码，解释这行执行时变量是什么值、发生了什么**
- 每一个新概念都解释缩写含义（def=define, str=string, int=integer）
- 代码遇到报错时，先解释错在哪，再给正确写法
- 不确定的地方直接问"你是不是想说XX？"确认

## 概念解释要点（来自真实教学经验）

以下概念是使用者问过的，需要准备好通俗解释：

### str() / int()
- `str` = string（字符串/文字）的缩写，把数字转成文字
- `int` = integer（整数）的缩写，把文字转成数字
- 类比：文字是给人看的，数字是给计算机算的，str()/int() 就是搭桥的

### with ... as
- 不是"随着"的意思，是固定句式
- 类比：借书——`with 借书证 as 借书卡:` 你拿书看，看完自动还书
- `open("文件","r")` = 开门，`as f` = 给这扇门起临时名字叫 f
- `with` = 承诺：离开这个代码块的时候自动关门（不用手动 f.close()）

### def
- define（定义）的缩写
- 意思是"造一个新功能"，以后想用就叫它的名字
- 类比：设定一个快捷指令，喊名字就执行

### 变量命名
- `count`、`result`、`f` 都是随便起的变量名，意思清晰就行
- `count` = 计数，`result` = 结果，`f` = file 缩写
- `+=` 中间可以加空格也可以不加，`count += 1` = `count = count + 1`
- 同理：`-=` 减等于、`*=` 乘等于

### utf-8
- 不是时区！是文字编码规则
- 告诉电脑"这个文件里的中文用什么规则存/读"
- 不加的话中文可能乱码

### 全角/半角括号
- 用户容易写成全角 `（）`（中文输入法默认），Python 只认半角 `()`
- 遇到 SyntaxError: invalid character '（' (U+FF08) 就是这个问题

⚠️ 关键教学点：**使用者可能把 `\"r\"` 当成\"不定代词\"（像 for f 里的 f 一样随便起的名字）**

❗ 需要特别强调区分：
- **变量名**（`as f`里的 f、`for f in`里的 f、`count`、`result`）→ 随便起
- **模式参数**（`\"r\"`、`\"w\"`、`\"a\"`）→ 固定写法，不能改

使用者原话：\"这个w和r也都只是不定代词吗？\"
👉 回答思路：不是不定代词，是固定参数。类比\"堂食\"（r）和\"打包\"（w）——你去饭店说的不是随便起的名，是告诉老板你要怎么吃。

### 文件内容 vs 屏幕输出（常见混淆）

```python
print(\"文件内容是：\")       # ← 这行只显示在终端屏幕上
f.write(\"这是我的文字\\n\")  # ← 这行才写进文件里
```

使用者第一次看到 test.txt 时发现里面没有\"文件内容是：\"这句话——因为 print 的内容永远不进文件。

类比：
- `print` = 我说话给你听（屏幕显示）
- `f.write()` = 我拿笔写在纸上（存进文件）

### 相对路径 vs 绝对路径

- `\"test.txt\"` = 相对路径 → 文件生成在终端当前目录（C:\\Users\\使用者）
- `\"C:/Users/使用者/Desktop/test.txt\"` = 绝对路径 → 明确指定桌面

使用者第一次跑时文件\"没出现\"，实际在 C:\\Users\\使用者 下面，不是丢了。

### r / w / a 模式参数的含义
- `"r"` = read（读取模式），不是随便起的名字，是固定参数
- `"w"` = write（写入模式），会覆盖原有内容
- `"a"` = append（追加模式），在末尾加内容不覆盖
- 这些模式在 `open()` 开门时设定，决定了后续 `f.read()` / `f.write()` 能做什么
- `as f` 里的 `f` 才是随便起的变量名（file缩写），可以换成别的
- 关键区分：变量名可以随便起（as f、as 文件、as x），但模式参数 "r"/"w"/"a" 是固定写法不能改
- 类比：去吃饭，跟老板说"堂食"（r）还是"打包"（w），定好模式后面就按这个来

### 相对路径 vs 绝对路径
- `"test.txt"` = 相对路径，文件生成在当前终端所在的目录
- `"C:/Users/使用者/Desktop/test.txt"` = 绝对路径，明确告诉Python存到桌面
- 初学阶段建议用桌面绝对路径，这样文件跑完一眼就能看到

### 文件内容 vs 屏幕输出
- `print("xxx")` = 显示在终端屏幕上，不进文件
- `f.write("xxx")` = 写进文件里，不显示在屏幕
- 容易混淆的点：初学者以为 print 的内容会进文件

## 关于 for 循环的重要教学点

使用者对 `for r in records:` 的理解困难在于：
- `for 变量 in 列表:` 这个句式里的变量（如 r）每轮循环被重新赋值
- 使用者需要的是**逐轮列出来**：
  - 第1轮：`r = "可乐：3元"` → 执行 `print("- " + r)` → 打印 `- 可乐：3元`
  - 第2轮：`r = "烟：20元"` → 执行 `print("- " + r)` → 打印 `- 烟：20元`
- 先把 `for` 的行为降维成「变量被依次赋值」，再讲「执行缩进的代码」

## 面向对象 class / NumPy / Pandas 教学要点（2026.8.4 实战）

### class（第8项）
- **理解锚点**：class=图纸，实例化（`d1 = Dog("旺财")`）= 照图纸造实物。使用者自己用"做一只大狗"理解，效果极好；顺势用"让大狗叫"（`d1.bark()`）巩固"方法=让实物干活的指令"
- **使用者写class练习的5个典型错误**（逐行指出让使用者自己改，不代写）：
  1. 参数误放函数体：`def __init__(self): (self,name)` → 参数必须写进 def 括号里
  2. 构造参数未接收：name/score 没在 `__init__` 参数列表 → NameError
  3. 实例化少传参数：`Student("土豆")` 缺 score → TypeError: missing 1 required positional argument
  4. 调用方法忘括号：`s1.jiao` 应为 `s1.jiao()`
  5. 字符串+数字拼接：`"考了" + 95` → TypeError，需 `str(95)`

### NumPy（第9项）
- 核心：np.array 数组做算术 = 逐元素运算（普通列表 `*2` 是复制两遍，数组 `*2` 是每个元素乘2）
- 需主动解读的输出细节：numpy 打印元素间是空格无逗号、除法结果自动变浮点（`[1. 2. 3. 4.]`）、`shape` 输出 `(4,)` = 一维4个元素

### Pandas（第10项）
- 核心：字典键→列名，值列表→列数据，`pd.DataFrame(data)` → 表格
- 输出细节：`df["列名"]` 返回 Series（结尾带 Name 和 dtype:int64）、`shape` 输出 `(3,3)` = 行在前列在后
- 使用者一次连过 class/NumPy/Pandas 三项，一天教3项节奏可行
- 详细教学日志见 references/session-20260804-learning-log.md

## Common Pitfalls

1. **替使用者写代码** — 绝对不行，代码必须使用者亲手敲
2. **跳过解释直接给答案** — 每次报错都要解释"为什么错了"
3. **用专业术语不解释** — str、int、def 这些缩写第一次出现都要说明
4. **用终端跑 input 代码** — input 需要交互，不能在后台终端跑
5. **不更新表格** — 每完成一项必须立即更新，不要等使用者提醒
6. **使用者问概念时深入解释** — 使用者会问`str是什么`、`def是什么意思`、`count是什么意思`、`+=为什么不用空格`、`result是啥意思`、`add呢`、`utf是时区吗`、`with...as怎么理解`、`r只是一个替代词吗` — 每个都要用类比举例讲清楚，不要只说"就是个变量名"
7. **不要替使用者跑代码检查结果** — 使用者跑完说"好了"时可以用终端验证，但在教学过程中不要替使用者写或改代码
8. **使用者说"等一下"时立即停** — 等使用者交代完再继续
9. **解释编程概念时先回答使用者的具体问题** — 使用者问什么答什么，不要扩展成一整节课的内容
10. **混淆print和文件写入** — 初学者容易以为print的内容会写进文件，要讲清楚"print=屏幕显示，f.write=写入文件"
11. **进度判断以Excel为准，会话旧说法不作数** — 2026.8实例：7月27日会话曾报"第一阶段11项全打勾"，但实际Excel显示第8-10项（面向对象/NumPy/Pandas）未学。开始教学前必须读 `桌面/大模型学习计划/00-总表.xlsx` + 对应分表确认打勾状态，不要凭之前会话里"全通关"的说法继续；用户改口"学程序"/"继续学习"时同样先核表再开课
