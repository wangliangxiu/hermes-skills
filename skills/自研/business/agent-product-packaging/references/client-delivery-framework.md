# 客户端交付框架（把私人小助手交付给散户客户）

用来回答「客户侧到底交付什么、装完他第一天能用吗、他得自己准备什么」。
对外统一用**「用户定制化的私人小助手」**这个说法——比合作方嘴里的「XX认知操作系统」一类名词实在，实质就是使用者天天在用的东西（大脑 + 技能 + 配置）换成客户的配置。

## 一、先立骨架：五层 + 一个底座

| 层 | 里面有什么 | 产出物 |
| --- | --- | --- |
| 认知 | 卖什么、卖给谁、凭什么是他、怎么收钱 | 一张「定位卡」（一页纸） |
| 内容 | 选题、素材、成稿、视觉、排版 | 一篇能直接发的成品 |
| 分发 | 账号与矩阵、发布方式、节奏 | 真的发出去的内容 |
| 数据 | 回收、复盘、迭代 | 一条能重复用的规律 |
| 变现 | 卖什么、在哪卖、怎么收 | 第一笔到账的钱 |
| 底座 | 大脑（agent：知道他是谁、有手艺、记得住事）、工具（出图/配音/搜索/拉数据）、账号与额度、环境 | 一套能跑起来的机器 |

骨架的三个用法：**安装包清单＝底座**；**技能包清单＝第二三四层**；**对接问表＝五层逐层问完，配置就出来了**。

立骨架阶段只列格子，不抠细节（行业话术、术语库、平台组合、发布节奏、定价都等有客户再填）。

## 二、三块标准件（所有客户都要，成熟度不同）

文字 / 图片 / 视频，每块内部都是「找题 → 加工 → 成品」。成熟度决定交付顺序，也决定分期收钱：

- 文字：最熟，能一路到可直接发的成品，基本全自动
- 图片：次之，要客户自己的 key，风格与质量由我方把控
- 视频：最重，时间和钱都最贵，出的是半成品要客户过一眼

→ 分期：文字先上 → 图片跟上 → 视频后补。

## 三、定制件（一个客户一个样）

**搜索动作是标准的，「盯什么」是定制的**：AI 圈资讯 / 政策招标 / 竞品动态 / 本地生活。
其余定制件：行业术语库、固定格式（公文/报告/合同）、客户特有平台、客户特有流程。

框架公式：标准件（三块＋底座）＋ 定制件（配置项）＝ 一次装包解决标准件，一份填表解决定制件。标准件做得越厚，定制件越少，单客户人工成本越低。

## 四、快速上手怎么成立（客户最关心的一条）

客户买的是**磨合成果的复制品**。长期磨合出来的是四样：知道你是谁、手上有手艺、知道怎么办事（输出格式/文件放哪/什么不许做）、记得过去做过什么。前两样靠装包预置，后两样靠填表生成。

三个预置 + 一个引导：

1. **预置画像**：装完填一张约二十行的表（行业、受众、平台、语气、主要要干的活、输出格式、绝不许碰的），填完自动生成他的配置与记忆
2. **预置技能**：只装他真正要用的五到八个，不是把几十个全塞给他（多了反而蒙）
3. **预置流程**：桌面一个入口，点开是「今天做什么」，不需要他研究这东西怎么用
4. **首次引导**：头一周它得主动——第一天直接帮他把第一篇成品做出来，看实物胜过读十页说明书

上手台阶（跟客户讲就按这个节奏）：第一天装好出第一篇 → 头三天定位卡＋发第一条 → 头一周整条链自己跑一遍、节奏定下来 → 头两周看数据做复盘 → 头一月第一笔钱到账。

## 五、客户端要准备的账户与 API（通用清单）

按能力分，每类只向客户要真需要的：

| 能力 | 必要性 | 向客户要什么 |
| --- | --- | --- |
| 大脑（思考/写作/判断） | 必需 | 一个带余额的模型 API key（账号实名）；国内可选 DeepSeek/通义千问/豆包/Kimi/智谱/MiniMax 或中转站 |
| 看图/审图 | 建议 | 支持视觉的模型 key（多数与大脑同一个） |
| 出图 | 按需 | 作图平台 API key＋余额（火山方舟/即梦、通义万相、商汤、MiniMax、智谱） |
| 出视频 | 后期可选 | 视频平台 API key（火山/字节、快手可灵、MiniMax 海螺），按条按秒算，贵 |
| 听（语音转文字） | 不用要 | 本地模型免费跑，只一次性下载模型文件 |
| 说（文字转语音） | 不用要 | 免费方案够用；要更自然音色再买 |
| 查资料（联网搜索） | 要 | 搜索服务 key（多有免费额度）或走免费通道 |
| 平台数据 | 可选 | 第三方数据服务账号（付费）；部分平台有公开接口能白拿 |
| 真自动发布 | 走到才有用 | 各平台开放平台开发者账号——个人实名一般不够，通常要企业主体＋审核 |
| 24 小时在线 | 可选 | 云服务器账号＋域名（可选） |

要填的账户信息合计三类：手机号/邮箱、实名与企业主体信息、各平台 key 与充值方式。
**价格与各家免费额度：真要用的时候逐家查证后再报，不凭印象报数字。**

## 六、三条必须提前说清的前提（跟合作方和客户都要说明，不留问题）

1. **电脑得开着**：在客户自己电脑上跑，关机就停。上云＝多一份服务器成本且要客户掏，之后「账号怎么登录」「钱怎么付」又是一堆事；散户画像（连电脑都不熟）先本地跑。
2. **额度是客户的钱**：跑得越多、出的图越多烧得越快。产品里必须有「今天花了多少」的显示，否则他哪天算账会觉得是我们在花钱。
3. **发布要人点**：生产全自动，最后那一下留给人。公众号可自动进草稿箱、他点一下发；其余平台只能做到成品打包好＋图文填好、他手机上点发布。全自动无人值守发布做不到，谁承诺都是骗人。

## 七、生图引擎接法（不自研绘图）

原则：专业的事交给专业工具，我方只做**接线 + 把关**；客户安装时填自己的账号/API，额度与费用他自己负责。

- **可插拔**：能调通的都接；一家不通自动换下一家（多引擎备份）。
- **兜底**：客户没 key 或没额度时，用本地渲染出设计图/文字卡，不让流程断。
- **三道质量活儿**（这是客户感觉到「它就是比我用得好」的地方）：
  1. 先出**配图清单**（哪一段配什么画面、什么风格、什么平台规格尺寸：小红书竖图 3:4、公众号头图 2.35:1、微博多图）再出图，不是生成一张随手贴上
  2. **风格模板统一**：同账号/同篇一套色调、构图、画风，几张图摆在一起像一套；模板做一次用一百次
  3. 出图后**用视觉模型自动审**（尺寸对不对、有没有崩坏、有没有乱码文字），不合格自动重出
- **只能接提供 API 的模型**；只有网页版账号的接不进来（不模拟浏览器点击）。
- **成本提示**：出图前给「这轮大概花多少钱」；合同写明 API 费用客户自付、额度用尽不算故障。

## 八、客户端看到的三样东西（交互定调）

一个安装包（双击装）＋ 一个能聊天的窗口（他说想干什么，它就干）＋ 一个放成品的文件夹（文章、图、视频，打开就在那儿）。**多一样都是负担。**

- 客户看到的绝不能是命令行黑框。
- 语音（麦克风/蓝牙耳机）是加分项不是必需项：能听能说，本地免费；但「喊一声就醒」要上硬件，不是装软件就能有。
