# 施工日志自动生成模板

## 适用场景

台车打完一个循环后，自动生成施工日志。数据来源：设计参数（软件自有）+ 台车传感器回传（实际钻孔坐标/深度/角度/推进参数）+ 操作员手动补充（异常备注、人员信息）。

## 日志结构（7个板块）

### 一、炮孔设计参数
自动从设计文件读取：
- 各类型炮孔（掏槽/辅助/周边/底板）的设计数量、设计深度、设计角度、圈径
- 合计孔数、设计进尺

### 二、实际钻孔记录
从台车传感器回传数据生成。每孔一条：
- 孔号、类型
- 设计坐标 (X,Y) vs 实际坐标 (X,Y)
- 实际深度、实际角度
- 偏差值 = sqrt((设计X-实际X)^2 + (设计Y-实际Y)^2)
- 状态标记：✅ 合格 / ⚠ 偏大

### 三、钻孔质量统计
自动统计：
- 偏差≤2cm → 优秀  2cm<偏差≤5cm → 合格  偏差>5cm → 不合格
- 最大偏差、平均偏差
- 质量评级

### 四、钻进过程参数记录
从台车传感器回传，每孔一条：
- 平均推进速度、平均冲击压力、平均回转扭矩
- 备注（正常/异常）

### 五、异常记录
自动检测 + 人工补充：
- 时间、孔号、异常类型、描述
- 自动捕获：推进压力异常升高、钻孔偏位超标、传感器校准

### 六、施工信息
- 台车编号、操作员、技术员、监理、全站仪操作（人工填写）
- 本循环施工时间、纯钻孔时间
### 七、下一循环建议

基于本循环数据分析，**纯规则（if-then）生成**，不依赖AI/不依赖网络：
- 围岩变化区域的参数微调提醒
- 偏差偏大区域的检查建议
- 整体质量评估

⚠️ 规则生成后显示在可编辑文本框中，操作员可以自己改或删，最后签字确认。不是AI生成的，不需要联网。

## 数据来源对照

| 日志板块 | 数据来源 | 字段类型 | 交互方式 |
|:---------|:---------|:--------|:--------|
| 设计参数 | 软件内部 | 只读 | 自动填充 |
| 钻孔记录 | 台车传感器 | 只读 | 数据回传不可改 |
| 质量统计 | 自动计算 | 只读 | 自动统计 |
| 钻进参数 | 台车传感器 | 只读 | 数据回传不可改 |
| 异常记录 | 自动检测+人工补充 | 混合 | 自动检测只读，人工备注可编辑 |
| 施工信息 | 人工填写 | 可编辑 | 下拉选择（预设选项）|
| 下循环建议 | 规则生成 | 可编辑 | 文本框自动填充后人工修改 |

## 最终输出格式

**最终交付物是 .docx（Word 文档）**，不是 txt/json。用 python-docx 生成，排版规范：

- 文件头居中大字标题「施 工 日 志」
- 项目信息区：2-3行文本
- 各章节用标题+表格排版
- 偏差超3cm的孔标红
- 底部签字栏（操作员/监理）
- 右侧生成时间水印

## 中间交换格式

台车工控机导出的是 JSON，不是直接生成 Word：
```json
{
  "日志版本": "v1",
  "项目信息": { ... },
  "设计参数": { "炮孔列表": [...] },
  "实际钻孔": [ ... ],
  "异常记录": [ ... ],
  "施工信息": { ... },
  "生成时间": "..."
}
```
JSON 是纯文本格式，Windows/Linux/PLC/嵌入式都能读写。你的软件负责读 JSON → 生成 .docx。

## 生成流程

```
打完一个循环 → 台车自动导出钻孔数据
  → 软件读取 → 匹配设计文件
  → 计算偏差 → 统计质量 → 检测异常
  → 追加施工信息（人工填）
  → 生成完整日志 → 存档
```
