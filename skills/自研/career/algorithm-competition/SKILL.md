# 算法竞赛参赛打法（Algorithm Competition Playbook）

## 触发条件
用户给赛题/比赛要求（如琶洲算法大赛、数据挖掘赛），问选哪题、怎么打、时间够不够、数据没到手能做什么时加载。

## 核心原则
1. **务实路线 > 学术天花板**：外部AI给的难点拆解往往"学院派"（克里金/SIPP/深度学习/毫秒级决策），参赛目标是"完整跑通+评分点全覆盖"，按评分结构倒推最小可行方案，别过度工程化
2. **评分点倒推**：把总分拆到每个评分项，方案设计逐项对应"这项怎么拿分"（如"阈值可解释性"→规则型阈值+公开标准依据）
3. **先跑通再优化**：第一版必须能交付，优化是剩余时间的活
4. **模拟数据先行**：真实数据未到时，用模拟数据把框架搭起来跑通（分级/寻路逻辑不依赖数据格式），数据到了只填数据+调参，能省 3-4 天
5. **提交留提前量**：截止日-1 完成联调，提交当天上午上传，不卡最后一刻（平台审核/网络不可控）；用户常要求提前提交，时间表按"提交日倒排"而不是"数据到手起算"

## 工作流
1. 读赛题 → 拆评分表 → 判断选哪题（技术门槛/数据可得性/用户背景匹配度——新手优先规则+寻路类，避开预测精度大头）
2. 方案设计：数据使用计划、模型选型、代码架构、提交物清单（txt 放桌面）
3. 模拟数据搭框架 → 自测抓 bug → 等真实数据
4. 数据摸底（字段/时间范围/缺失率）→ 清洗 → 网格化
5. 调参校准 → 评估指标 → 报告（含异常场景记录）→ 部署文件
6. 联调 → 提交

## 规则型模型技巧（风险分级/阈值类）
- **阈值方向性是最大坑**：风险要素分两类——"越大越危险"（风速、降水）和"越小越危险"（能见度、雷电距离）。配置里必须给每个要素标 `direction: higher/lower`，分级逻辑按方向比较，否则会全判成最高等级（琶洲赛题实证：雷电距离50km被误判禁飞）
- 综合定级用"最不利原则"（取各要素最高等级）——安全优先、可解释性好，正好踩"阈值可解释性"评分点
- 阈值初值参考公开标准（气象预警等级、设备标称参数如无人机抗风6级≈10.8-13.8m/s），数据到后用分位数统计校准
- "模型权重文件"可以用阈值配置文件（JSON）——天然可加载可复现，满足提交要求

## 自测要求
- 分级模型自测案例必须覆盖"安全 case"（全低风险要素）验证不误报，再覆盖逐级递增 case
- 寻路自测要有"必须绕行"场景（中间设禁飞区）验证绕行逻辑

## 常见坑
- 数据审核/下载延迟：组委会数据常要1-2个工作日审核，别把关键路径压在数据到手后，框架先行
- 平台说明："XX平台只提供数据下载+作品提交，不提供在线训练环境"→ 本地开发完全合规，不用在平台搭环境
- 提交格式（"主测试脚本需符合平台接入规范"）最后做：多半只是文件命名/打包要求，看平台上传页说明即可，不用提前对接
- 用户对 token 费用敏感：写代码/跑测试/多路调研等重活默认挪到非高峰时段（18点后）做，先问用户
