# 照片组 → 运镜视频提示词包

## 触发

使用者丢来一个文件夹的照片，说"做成视角移动的视频""生成视频提示词""按镜头顺序把图片编号""调用导演工具"。

产出三件套（全部落盘，别只在回复里写）：重编号后的图片、`分镜与提示词.txt`、`分镜板.jpg`。

## 步骤

### 1 盘素材

- 列目录记文件名/大小；用 PIL 读尺寸确认画幅（常见 2048×1152=16:9）。
- 拿不准哪张是哪个画面，先看联系表（第 3 步），不要靠记忆把 8 张图对齐。

### 2 看图（最容易翻车的一步）

- 大图（>2MB）**一次最多看 1–2 张**，看完**立刻**把观察写进 `素材观察笔记.txt`，再继续下一张。
  原因：多图进上下文后会被裁剪（结果里出现 `[screenshot removed to save context]` 就是被裁了），
  几轮之后图就不在上下文里了，这时凭印象写提示词＝瞎编。图被裁过又记不真切，就重新载一次再看。
- 只写看见的：匾额/碑文/对联读不出就写"不可辨"，不猜景区名、人物身份、年代。AI 生成图里的文字基本是伪字。

### 3 联系表 / 分镜板（PIL，一次生成两用）

```python
from PIL import Image, ImageDraw, ImageFont
font = ImageFont.truetype(r"C:\Windows\Fonts\msyh.ttc", 26)   # 中文标签必须显式给字体，否则方块
# 4 列 × N 行；每格 480×270，格上方 36px 黑条写 "镜NN 简短描述"（黄字），再 paste 缩略图
```

- 用途一：核对"文件名 ↔ 画面内容 ↔ 镜号"的映射，避免张冠李戴。
- 用途二：直接作为 `分镜板.jpg` 交付，使用者一眼看全片顺序。

### 4 排镜头顺序

按导演节奏排：大远景建立 → 主体亮相 → 全景抵达 → 第一人称中景推进 → 前景特写过渡 → 全景高潮 → 框景收束 → 横移离场。

- **禁连续三镜同一景别**；每镜 4–5s，总时长要报出来；转场标"淡入/叠化/硬切"。
- 顺带给一版 15–20 秒短版方案（保留 5 镜）。
- 运镜术语、景别、转场对照见 `references/camera-move-vocabulary.md`。

### 5 按镜头顺序编号 = 就地改名

`镜01_牌坊广场大远景.png`、`镜02_金色帝王像.png` … 直接 `os.rename`，**不另建副本**（省空间），
原文件名写进提示词包里的对照表，随时可还原。交付时把新名和原名一起报给使用者。

### 6 写提示词

每条按 **中文 7 层结构**分条，不要堆成一大段：
主体 / 动作 / 环境 / 运镜 / 光影 / 氛围·风格 / 技术参数（16:9、4K、24fps、图生视频首帧＝对应图片）。
后附英文对照 + 负向提示词；每镜 4–6 行。

- 运镜用标准术语（Slow Dolly In、Tilt Up、Truck Left、FPV、rack focus），**一条镜头只写一种运动**。
- 只写"镜头怎么动、画面里什么在动"，**不要重新描述画面内容**——重复描述会和首帧打架，直接导致建筑变形、透视崩塌。

### 7 交付物

全部放 `桌面\我的小项目\<任务名>\`（txt 不用 md，见 desktop-organization-rules）：

- `分镜与提示词.txt` — 主产出：镜头总览表（镜号/文件/景别/运镜/时长/转场）+ 通用生成规则 + 逐镜提示词 + 编号对照表 + 工作流；
- `素材观察笔记.txt` — 逐张观察记录，注明"编号为文件名排序，不是镜头顺序"；
- `分镜板.jpg` — 带镜号标签的缩略联系表。

## 坑

- **水印会被烧进视频**：豆包/即梦等生成图右下角有"XX AI生成"水印，直接当首帧＝水印入片。先裁掉右下角（约 420×90px，不动构图）或后期遮罩；动手前先问使用者要不要一起处理。
- **AI 伪字**：匾额、碑文、对联都是乱码字，别给文字特写、别让镜头停在文字上；运镜一律设计成"缓慢移动不停顿"，否则一推近就露馅。
- **动态坍塌**：AI 图生视频怕运动叠加。一镜一运动、幅度小、速度慢；画面内只让灯笼摆、香烟升、旗子飘、树枝颤，**建筑/石狮/石灯等硬物必须完全静止**（石头会动就废了）。
- 每镜建议生成 2–3 条，挑建筑不变形的那条。
- 素材是 AI 生成图时，空间关系未必自洽（"同一景区"可能冒出几座形制不同的殿）。照图写镜头即可，别硬写成一套建筑考据，也别据此推断景区名。
- 全片色调统一（统一暖调或统一冷调），否则各镜白平衡打架。
