# 用脚本生成长篇 Word 文档

适用场景：几十页到上百页、章节结构固定的正式 Word 文档，且会反复整体改 ——
投标文件 / 施工组织设计、研究报告、手册、说明书、汇编。
用户常用的说法：生成这份文档、按这个结构出一份 Word、重做一版、把内容套成正式文件。

不适用：短文档与单张表；往已有模板里填空（用模板替换的做法）；只改几处的批注或格式调整。

## 为什么走脚本，不走手写

手写 Word 改一轮就散架 —— 字体、编号、目录、表格口径全漂。脚本把内容与排版分开：内容写在脚本里，
改一处重跑一次，全篇一致；每轮重生成还能顺手把自查做一遍。前提是**章节结构先定死**：结构没定就动笔，
返工的是整份文档。

## 工作流（照这个顺序做）

1. **先定结构与素材清单**：章节骨架（来自对方的格式要求 / 评分标准 / 目录要求）+ 每章素材出处
   （哪份文件、第几页 / 第几章）。素材没到位的先占位并列入"待补清单"，**不要停下来等**。
   - 素材是几百页的 PDF 时：先按书签把它切成一章一个 txt（PyMuPDF 的 `get_toc()` 给出章节页码），
     再逐章读 —— 不要整本塞进上下文
   - 厚章节（合同条款、清单这类）交给并行子任务读，要求它们把笔记**写成带出处的文件**
     （每条标原条款号 / 页码），只把摘要回传 —— 笔记落盘后可直接当引用来源反复用
   - **抽到参数后回头回填**：把原稿里"按设计 / 按实际确定"这类含糊处换成抽到的具体量（规格、
     材料强度、里程、净距、数量），这是对方看出"这份文件照着他给的东西写的"的地方；
     抽不到的就留着并标"按……核算后填报"，不许估一个看着差不多的数填上去
2. **内容分批，一批一个脚本**：每批对应一个大类（编制依据与概况、方案、资源计划、质量安全、
   进度与文明施工、附表……），一批一个 `.py`。
3. **第一批 `Document()` 新建并保存，后续批次 `Document(路径)` 打开 → 追加 → 保存**，
   同一个 docx 逐批长出来。
4. **重生成时按顺序重跑全部批次**（第一批覆盖整个文件），一条命令跑完；
   只跑其中一批会得到半份文档。
5. **用 Word COM 更新目录域并导出 PDF**（目录页码只有 Word 能填，python-docx 只写得进域代码）。
6. **把 PDF 每页渲染成 PNG，逐页看一眼**（空白页、越界、字体、表格挤压、插图错位）——这步不能省。
7. **交付**：成稿 docx + PDF 预览 + 附图原图 + 说明与自查表，装进同一个任务文件夹。

## 硬坑（每条都是真栽过的）

- **分页别用 `add_page_break()`**：前一段刚好填满页时，分页符会在新页生成一个空段落，白出一整页。
  改成给下一章标题设 `paragraph_format.page_break_before = True` —— 段落已在页首时不会多分页。
- **一定查空白页**：渲染每页取文本，字符数近 0 且无图的就是空白页，必须修掉；正式文件里的空白页是硬伤。
- **表格行数按数据算**：写一个 `TB(headers, data)` 助手，行数 = `1 + len(data)`；
  手写死行数再传数据，必然 `IndexError: list index out of range`。
- **合计/总计一律代码算**：表里的"合计"行用 `sum()` 生成。手算会错，而且没人会逐行验，
  交出去就是数据自相矛盾。
- **自动目录要求标题走 Heading 样式**：自定义加粗段落不进目录。用 `doc.add_paragraph(style="Heading 1")`，
  再用 run 覆盖中文字体并强制黑色（否则是默认的 Calibri 蓝）；一级标题顺手设 page_break_before。
- **列多的宽表放横向页**：`doc.add_section(WD_SECTION.NEW_PAGE)` + `WD_ORIENT.LANDSCAPE` + 页宽高对调
  （横版是宽 29.7、高 21.0），否则十几列的表挤成一团。
- **导出 PDF 前别先删旧 PDF**：先 `os.remove` 再 `SaveAs`，保存一旦失败就什么都不剩。
  先存成功、再替换旧文件。
- **Word COM 会掉线**（报"被调用的对象已与其客户端断开连接"）：taskkill WINWORD 后重新打开一次，
  不要在同一个实例上硬重试。
- **插图改了要重跑**：图片文件改了内容或改名，文档里还是旧图；图片更新后至少重跑插入它的那一批。
- **数字要有出处**：文档里填的量、参数、比值，能查到出处的标出出处（清单 / 文件 / 勘测），
  查不到就写"按……核算后填报"，**不许编**；表里的数一律来自素材，不做"看起来差不多"的估算。

## 交付形态（用户偏好）

- 记录类 / 说明类文件用 txt，正式文档用 docx
- 交付物按任务建**一个顶层文件夹**装齐（正文、PDF、附图、说明、自查表），桌面不放散件
- 正式文档都要配一份**完整性 / 符合性自查表**，分开写清两件事：哪些是文件层面已达标（章节齐、
  格式对、明文要求已响应），哪些必须拿实际资料才能填 —— 别让"框架齐了"被读成"可以交了"
- 自查要**实测**：把成稿的标题逐级打出来数章数、把关键内容词在全文里搜一遍，搜不到的就是真缺
