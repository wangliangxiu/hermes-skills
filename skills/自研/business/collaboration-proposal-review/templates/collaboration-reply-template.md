# 给合作方的回复（骨架模板）

语气：书面、客气，但不含糊——该说做不到的直说，不写成「条件受限」这类软话。称呼按对方身份（「X 先生/总」），落款带姓名、日期、电话。

```
关于《<文档名>（<版本>）》的回复

<对方称呼>您好：

文档我已逐章读完（<读的范围：全文/简版全篇>）。下面按「我对文档的判断 → 技术侧能做到什么程度 → 需要先定清的地方 → 建议的下一步」四块回您，直说无保留，也请您逐条指正。

一、对文档的判断
1. 先给一条具体的肯定（认可了哪条原则、哪段排期口径不虚），说明我认真读了
2. 指出「有一类目标问题不在工期，在平台权限/资质」，把 C 档提前暗示

二、技术侧能做到什么程度（按快慢直说）
A. 能独立交付，且快（天级到一周）：条目化列出，并标注对应文档编号
B. 能做，但要时间、会有反复（周级到两三周一项）：条目化
C. 现阶段做不到的，我直接说：每条写清机制原因，并给出「只能退到什么程度」的现实落法
D. 需要您方出人出资质的部分：账号与实名主体、营业/支付资质、存量素材整理、外部顾问事项

三、文档里建议先定清的 N 处
（自相矛盾的验收项 / 时间口径版本 / 交付物与许可冲突 / 缺章要详版 / 实名与责任 / 预算与报酬）

四、合作条款方面，希望开工前先谈清
1 投入方式  2 报酬与结算节点  3 费用谁出与预算  4 范围写死（以文档编号为准）
5 验收方式  6 知识产权归属  7 账号实名与责任划分  8 变更与终止

五、建议的下一步
1. 请先发详版（列出简版缺失的章节号）
2. 用实际账号做一次平台权限实测（列要测的平台）
3. 先做一件 3 天内可交付的小活，按小活结一次账，双方都踏实

以上是我的直白判断，其中「做不到」的部分是真的做不到，不是保留条件。

<姓名>
<日期>
电话：<电话>
```

## 交付方式

- 存成 txt（不要 md），放 `桌面\我的小项目\<任务名>\`，回复里直接贴全文供使用者复制，并附绝对路径
- 收尾给使用者「可调的两处，你定」：例如条款清单要不要放进初次回信、落款身份怎么写（这个措辞影响后面谈报酬的口径）
