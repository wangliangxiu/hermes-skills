# 核实"AI 工具推荐文/软文"可信度

触发：使用者丢来一条 X 帖 / 公众号文章 / 视频文案，可能只给链接不给指令，或明说
"核一下这篇文章靠不靠谱"。要的是**判断**，不是复述。先按 SKILL.md 第 5 节抓正文
（X 长文走 `tweet.article.content.blocks`），再走下面的阶梯。

## 核验阶梯（按顺序，每步都能出结论）

1. **产品是否真实存在**：curl 官网首页，看能不能打开、`<title>` 是什么、有没有中文页。
   打不开 ≠ 不存在（可能 SPA），换 /zh、/docs 再试。
2. **官方支持矩阵 —— 最大的漏洞通常在这**：抓官网 `/docs` 索引页，把所有文档 slug
   列出来，再抓跟文章声称功能相关的那几页（如 agent-plugin、desktop-app、
   free-and-pro、pricing）。推荐文爱把"支持某几个具名客户端"写成"支持任何 Agent /
   任何模型"，官方文档一列就现形。文章捧的那条路若不在官方列表里，判定为
   野路子：能用不代表官方保证，随时会因插件更新断掉，必须明说。
3. **免费/付费边界**：抓 pricing 页和 FAQ，把"零成本"拆成三问——哪部分免费、
   哪部分要积分、新用户送多少。软文最爱拿"编辑器免费"含混成"全流程零成本"，
   把要付费的生成能力（视频/图片/配乐/MG 动画）一句带过。
4. **订阅与价格声称**：跟官方价对齐（官网或搜索结果）。凡出现"几块钱/十几块钱
   买十几个月会员、账号"= 拼车号或黑卡号，违反 ToS、随时掉线、可能连带封掉
   使用者自己的正规账号——直接判"不能抄"并明确劝退，不要中性描述成"性价比渠道"。
   顺手核实作者拿权益当卖点的地方（如"家庭组能加 5 人"本是给家人的权益，
   被讲成多号轮换刷额度）。
5. **模型名与单价**：模型名、价格、上下文长度用 web_search 核（官方文档/博客优先）。
   作者"随便改不心疼 token"这类说法通常隐含"你已有订阅"，把它还原成前提条件；
   贵模型（按每百万 token 计价的高端模型）价格可作"他说得对"的证据。
6. **推广动机信号**：作者主页挂 CPP/商业合作/代言标识、结尾引流（"要不要我做一期
   视频教程"）、产品官网同期挂限时折扣位 → 按软文标准读。可以点明动机，但**不要
   扣"撒谎"帽子**，语气是"这不代表他撒谎，但你要按软文读"。

## 输出结构（使用者接受的形态）

1. 开头一句结论：方向真/假、有几处错、能不能照抄（"当读物可以，当教程不行"）。
2. 说对的部分——逐条附我验过的依据。
3. 说错/夸大的部分——每条写清：错在哪 + 正确事实是什么 + 从哪来的。
4. 推广动机判断。
5. 一句话总结（把纠正后的完整结论压缩成一句）。

纯文本排版（CLI 不渲染 markdown），不用星号/井号做标题，靠缩进和空行分层。
中间过程不汇报，查完一次性交付。

## 纪律

- 每条结论带来源（官网文档页 URL、搜索结果），查不到就写"核不到"，不替作者圆。
- 作者的口误（转写错字，如把 Codex 写成 Codes、把 Antigravity 写成 Anti gravity）
  单独一句带过即可，不影响结论。
- **不动使用者的机器**：不装软件、不注册账号、不改配置。核完先给判断，再问要不要落地。
- 使用者选"先不动，只核一下"时，就不要顺手存文件、写报告——按他说的只出判断。
