# 电脑硬件升级与选型咨询

适用：用户问"我这台能不能加内存""加两条 8G 行不行""该买哪张显卡""笔记本还是台式""现在该不该买"。

## 铁律（每条都是踩过的）

1. **先确认是哪台机器。** 本机 ≠ 用户要问的机器。terminal / PowerShell 查到的硬件只代表跑 Hermes 的这一台；用户常在问另一台（家里的台式）。认错机器的后果是整段建议作废，还得从头重来。
2. **开口前先翻会话记录。** 用户报过的配置（CPU、主板、内存、显卡）先用 session_search 调出来，绝不让他重报一遍，他会直接不满。回忆类问题先凭已有上下文答，别先跑一堆工具让他干等。
3. **规格只认型号，线索推不出结论。** 内存槽数、最大容量、支持频率必须落到主板的具体型号（用户机器：Win+R → msinfo32 → "基板型号"；本机：Win32_BaseBoard）。SATA 口数、品牌印象、"我记得是 XX" 这类线索**推不出**内存槽数——"4 个 SATA + 2 个内存槽"是 H610 常见组合，用 SATA 口推槽数必错。凡是推断出来的，必须写明是推断并请用户核一眼型号，不能当事实陈述。
4. **分两件事答：插得下 ≠ 跑得稳。** 能不能插是槽位问题；跑不跑得稳是平台问题（内存控制器 + 芯片组 + 几条 rank）。只答一半等于没答。
5. **价格现查，不报记忆价。** 内存/显卡价格波动极大，每次重新查并标注"查价日期 + 口径"（渠道价 / 行业报价 / 零售 / 二手）。
6. **算净支出，不只看买入价。** 旧件在高位时卖掉能回血，所以"卖旧换新"的净支出常低于"加装"——这个对比要算给用户看。
7. **指出真正的瓶颈。** 用户问的部件经常不是卡住他的那个（问内存、其实卡显存）。发现就直说，别只顺着问题答。

## 流程

1. **定位机器**：读 `references/machine-ledger.md`（本机 / 家里机器台账）；台账里没有的，一次性问全（CPU、主板型号、内存型号、显卡、用途、预算），不要来回追问。
2. **拿型号**：本机侧用 write_file 落一个 .ps1 再 `powershell -NoProfile -ExecutionPolicy Bypass -File`，查 Win32_BaseBoard / Win32_PhysicalMemory / Win32_PhysicalMemoryArray（bash 直接传 `-Command` 时 `$` 会被吃掉、中文还会乱码，落脚本最稳）。**MaxCapacityEx 常误报，不要单独采信**（实测有机器报 16GB、官方实际支持 32GB）。
3. **查官方规格**：主板厂商规格页（DIMM 槽数 / 最大容量 / 标称最高频率 / QVL 内存支持列表）；笔记本机型查 Kingston 内存查询（kingston.com/memory/search/<品牌-型号>）拿"槽数 + 最大容量 + 频率上限"，再用厂商社区帖交叉验证。**同一芯片组不同主板规格能差一倍**（H610 主流 2 槽，也有 4 槽板），查到具体型号为止。
4. **套平台限制**：见 `references/platform-limits.md`。
5. **出方案**：按"最省 / 标准 / 上限"三档，每档写清买什么、得到多少、代价是什么（降频、混插风险、占槽）。**永远优先两条大容量，不推荐四条小容量**；真要满插四条，要求同品牌同型号同颗粒。
6. **价格与净支出**：查实时价（行情源见 platform-limits.md），把"加装"和"卖旧换新"的净支出列成对比再下结论。

## 输出风格（使用者的要求）

- 结论放最前（能/不能、值/不值），理由在后；中文、纯文本（CLI 不渲染 markdown，别用星号当排版）
- 不确定就直说查不到，**不许编型号、编价格、编参数**
- 数字要能追到来源（厂商规格页、官方查询工具、行情网站），他会自己核
- 他明确说过的事实（"我有 4 个内存槽"）直接采信，不要拿自己先前的推断顶回去
- 说完结论再问信息，且一次问全（型号 + 内存标签 + 用途），别一问一回合
