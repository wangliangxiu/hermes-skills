# 黑客松（链上/技术类）：平台要点与提交清单

来源：Avalanche Buildathon（Team1 China / OpenBuild 主办，2026-09 期）官方手册，剔除期次专属信息后保留可复用部分。

## 通用硬门槛与提交材料

大多数链上黑客松的硬性要求一致：

- 项目**必须已部署到该链上**（测试网可演示，主网更稳）
- 项目**必须能实际演示**，只靠 PPT 讲故事不算
- 代码完整、可运行，一般要求公开仓库（GitHub）

提交材料（四项，按这个结构准备）：

1. 项目介绍（问题 / 方案 / 亮点）
2. Demo 演示（视频或可访问链接）
3. 技术架构说明（具体怎么用上平台能力）
4. 代码仓库（GitHub 链接）

评审维度：创新性 · 与平台技术的相关性 · 代码完整性 · Demo 展示水平 · 方向多元性。
Demo Day 常要现场实操 + 讲未来规划 + 给仓库链接。

## Avalanche 考点（2026 期手册）

- 三链架构：**C-Chain**（EVM 兼容，Solidity 直接写合约）、**P-Chain**（质押与 L1 管理）、**X-Chain**（资产收发）
- **Avalanche L1**（原 Subnet）：应用专属链，独立共识 / Gas 规则 / 验证者集合；Avalanche9000（Etna）后部署成本约 **1.33 AVAX/月** → 叙事点"每个场景（如每个工地、每类设备）起一条自己的链，数据主权归场景方"
- **HyperSDK**：Go 框架，做自定义 VM
- **ICM / AWM / ICTT**：跨链消息传递与代币转移
- **x402**：面向 AI 时代的按次微支付标准，是官方反复点名的热点（赛题引导原文："AI Agent 如何在链上可信、自动地完成支付"）
- 卖点话术：高频数据能上链，靠的是亚秒级最终确认 + 极低 Gas，不用在性能与成本之间取舍

## 环境准备（Windows，本机实证）

两条路都行，**本机已跑通的是 Python 那条**：

### Python 路（已实证，推荐）

- 建环境：`py -3.13 -m venv "D:/venvs/<项目名>"`
  - **必须用正斜杠原生路径**：写成 `/d/venvs/xxx` 会静默失败（bash 的 MSYS 路径不会翻译给原生 python，命令退出、几乎无报错）
  - **挑 3.13 而不是最新版**：先 `py -0p` 看本机装了哪些；最新大版本常缺依赖 wheel
  - venv 放 D 盘，不占 C 盘
- 装库走镜像：`.../Scripts/python.exe -m pip install web3 py-solc-x -i https://pypi.tuna.tsinghua.edu.cn/simple`
- 私钥文件放用户目录（例：`~/.<项目名>/testnet_wallet.json`），**绝不放进项目目录**；项目里写 `.gitignore` 屏蔽 `wallet*.json`、`.env*`、`build/deployed.json`
- 部署路径：Python 脚本（web3.py）→ Fuji 测试网 → snowtrace 看交易 → 前端连 RPC 做可点演示

### 本地链：Foundry 的 anvil（合并本机实证，强烈建议装）

本地链是调试合约的唯一正确姿势：改一次跑一遍，验证过再上测试网。

- **别再走 Python 的 eth-tester / py-evm 那条路**：它依赖 `safe-pysha3` 这类 C 扩展，Windows 上要 MSVC 工具链，装不上就整条路断掉，别在那上面耗时间。
- 装 anvil = 下一个单文件二进制，放 `D:\foundry`：
  ```bash
  curl -s --proxy http://127.0.0.1:17890 \
    https://api.github.com/repos/foundry-rs/foundry/releases/latest -o rel.json
  # 从 rel.json 里找 browser_download_url 中带 win32_amd64 的那条（资产名是平台专属的，
  # 形如 foundry_v<版本>_win32_amd64.zip；写 latest/download/foundry_stable_windows_amd64.zip 会 404）
  curl -sL --proxy http://127.0.0.1:17890 -o foundry.zip "<上一步拿到的 URL>"
  unzip -o foundry.zip && ./anvil.exe --version
  ```
- 起链：`anvil.exe --port 8545 --host 127.0.0.1`（后台常驻）。就绪自检：对 `http://127.0.0.1:8545` POST `eth_chainId`，返回 `0x7a69`（31337）即可。
- anvil 的账户来自公开助记词 `test test ... junk`，`Account.from_mnemonic(..., account_path="m/44'/60'/0'/0/<i>")` 就能拿到私钥，本地测试无需管密钥安全（但也别把它写进部署到测试网的路径里）。
- 一套代码同时支持本地与测试网：用环境变量切 RPC（如 `CAISHEN_CHAIN=local|fuji`）+ 一个 `chain.py` 封装（连节点 / 取私钥 / 发交易 / 存已部署地址），本地与线上只差一个变量。

### 界面自检：用 Playwright 自己看渲染结果（AI 没有眼睛，必须装）

```bash
.../Scripts/python.exe -m pip install playwright -i https://pypi.tuna.tsinghua.edu.cn/simple
PLAYWRIGHT_BROWSERS_PATH=D:/ms-playwright .../Scripts/python.exe -m playwright install chromium
```

- `PLAYWRIGHT_BROWSERS_PATH` 指到 D 盘，别占 C 盘；之后每次跑截图脚本都要带这个变量。
- 写一个 `tools/shot.py`：手机视口（如 430×932、device_scale_factor=2），按参数抓**三态**——首屏、点主按钮后的弹层、交互完成后；顺手注册 `page.on("console")` 把报错打出来（界面静默出错比崩掉更难查）。
- 截图后**自己用 vision 看**，逐条挑毛病（对齐、截断、遮罩、层级），改完重截，改到顺眼再给使用者看。

两个必踩的前端坑：

1. **`[hidden]` 被 `display` 规则覆盖**：给弹层写了 `.sheet{display:flex}` 之后，`hidden` 属性就压不住它，弹层常驻页面上挡住所有点击。Playwright 的报错是 `subtree intercepts pointer events`。解法：全局加 `[hidden]{display:none !important}`。
2. **CSS 动画的 transform 会覆盖 SVG 元素自身的 transform 属性**：给带 `transform="translate(x y)"` 的 `<g>` 加了一个只写 `translateY` 的浮动动画，元素会塌到原点（表现是某个部件跑到画面角落）。解法：外层 `<g>` 只负责定位、内层元素负责动画。

## 多端交付（一套网页同时喂手机 / PC / 可安装）

一个网址、一套代码，别做两套页面或多套技术栈：

- **手机（默认形态）**：单列竖屏（430×932 起调），按钮拇指够得着，主形象在上、面板在下。
- **PC 宽屏**：`@media (min-width:960px)` 下用 CSS grid 分栏。**必须用显式 `grid-row` / `grid-column` 给每块指定位置，不要为了分栏去改 DOM 顺序**——DOM 顺序一动，手机上的阅读顺序就乱（会出现"先看到三个面板、最后才看到主形象"）。
- **PWA（手机"添加到主屏幕"即全屏 App，不需要上架审核）**：
  - `manifest.webmanifest`：`name` / `short_name` / `start_url` / `scope` / `display:standalone` / `orientation` / `background_color` / `theme_color`，icons 给 192、512、512 maskable 三张
  - `sw.js`：静态资源缓存优先；**`/api/` 一概不缓存**——余额、份额这类数据必须实时，缓存住演示时会显示旧数
  - `index.html` 引 manifest + `theme-color` + `apple-touch-icon` + `apple-mobile-web-app-capable`；`app.js` 里 `navigator.serviceWorker.register("/sw.js")`（只在 http/https 下注册，file:// 打开会报错，加个协议判断）
  - 图标不要手画 PNG：用 Playwright 打开一段 HTML（渐变底 + 一个大字）按尺寸各截一张，字体与观感跟界面天然一致；maskable 版把图形缩到约 56% 留安全边
- **别顺着"要不要做原生 App / 桌面安装包"往下做**：上架要审核、评委不会为了看 demo 装应用、对外传播为零，成本是几天级；上面这套多端补齐是半天级。这句话讲一次就够，讲完照使用者的决定办。

## 编译与部署：本机踩过的坑与可复用写法

- **solc 是原生程序，处理不了中文路径**：`solcx.compile_files([含中文的路径])` 报
  `invalid UTF-8 byte at index 8: 0xF5`（命令行参数被按非 UTF-8 解析，不是源码问题）。
  解法：Python 把源码读成字符串，走
  `solcx.compile_source(src, output_values=["abi","bin"], solc_version="0.8.26")`
  ——不让路径进命令行。跑 `scripts/compile_sol.py` 即可。首次会下载几十兆的编译器（固定版本）。
- **web3 v8 的交易写法**：`acct.sign_transaction(tx).raw_transaction`（v8 是 `raw_transaction`；老写法 `rawTransaction` 会 AttributeError）。字段：`nonce=get_transaction_count`、显式 `chainId`、`gas=estimate_gas*1.3`、`maxFeePerGas=gas_price*1.5`、`maxPriorityFeePerGas=1 gwei`。
- **开工自检三步**（与选题无关，随时可做）：① RPC 打 `eth_chainId` + `eth_blockNumber` 确认在出块；② `Account.create()` 建测试钱包并查余额；③ 部署一个最小合约，**立刻"写一笔记录 → 读回来 → 把 explorer 链接给使用者"**——链上可点的证据比"脚本跑通了"有说服力。
- 价值载体的合规边界（为什么链上只记凭证、算力/积分不上链）见 `涉链项目合规红线（中国境内）.md`。

## 选题菜单（工程/施工行业背景 → 链上，可复用）

1. **机械设备"链上机时台账 + 租赁自动分账"**（首选，差异化最强）
   - 痛点：机械设备租赁（旋挖钻机/挖机/凿岩台车）机时永远扯皮——机手记的工时、甲方签的台班、老板算的结算，三本账对不上；油料异常、窝工空转没证据
   - 做法：设备端定时把开工/工时/工况/位置签名后上链存证；租赁合同写成智能合约按机时自动算钱并分账；各方在网页上随时查这条不可篡改的记录
   - 优势：使用者台车项目本来就在采设备数据（钻孔记录、定位、参数），业务逻辑张口就来，别人编不出这些细节
   - 平台相关性：高频设备数据上链 = 亚秒确认 + 低 Gas；未来每工地一条 L1
2. **施工班组记工与工资存证**（公益向，难度最低的兜底）
   - 痛点：农民工工资拖欠、工长记工与工人记工两本账对不上，出事没证据
   - 做法：扫码打卡/工长记工 → 链上电子工票 → 按工票自动结算发放
   - 评审"方向多元性"常照顾公益类
3. **建材进场验收溯源**（钢筋/水泥防调包）：做法直白，差异化低、容易撞车
4. **AI Agent + x402 微支付**：按次付费调用 Agent 服务。官方热点、平台相关性分最好拿，但撞车概率最高，且会丢掉使用者的行业差异化 → 只当主线配件，别当主线

选择顺序：优先 1；周期紧或队友弱时用 2 兜底；4 只做配件。

## 术语白话表（讲给零基础的人）

| 词 | 一句话白话 | 落到本类项目里是什么 |
|---|---|---|
| 智能合约 | 放在链上、谁都能调用但没人能偷改的一段自动执行规则 | 存证类：那台"存证机器"；分账类：那份自动分账规则 |
| 合约交易（期货） | 金融市场上赌涨跌的产品 | **跟本比赛无关**，中文撞词，先破掉这个混淆 |
| 部署上链 | 把代码真的放到链上、拿到一个永久地址 | 没部署=代码只在自己电脑里、能随便改，评委只能看到 PPT |
| Gas | 每次调用合约要付的手续费 | 平台"极低 Gas"就是说高频小额上链才划算 |
| L1 | 自己单独起一条链 | 一个场景（工地/设备群）一条链，数据主权归场景方 |
| x402 | AI 时代的按次微支付标准 | 让 AI Agent 自主完成小额支付 |
| agent loop | 模型自己想→调工具→看结果→再决定下一步，循环到干完 | 判断标准：下一步谁决定的？人决定=普通程序；模型自己决定=agent loop（单纯"能调工具"不算） |

## 组队招募语模板（长短两版）

长版（发群自我介绍，四个板块顺序固定：能力 → 我在做什么 → 我缺什么 → 低门槛收尾）：

```
已报名，单人在冲，想找个搭子。方向还在挑（A / B / C 三选一），不耽误一起聊。

我擅长的：
· Agent loop：自己写过（工具注册表 + tool_calls 循环那套），平时重度用 agent 干活
· 行业背景：多年施工经验，投标技术标、BIM 熟，做过一套智能布孔系统（桌面软件）
· 内容运营：媒体出身，公众号、文案、排版、路演稿都能兜
· 强项是能把项目做成"能演示、能讲清楚"的样子——产品结构、Demo 脚本、提交材料

我缺的：链上合约这块想找个人搭。
娱乐为主，不卷，有兴趣滴滴。
```

短版（回复别人的招募帖，一行能力 + 一行缺口）：

```
我这边：agent loop 自己写过，code agent 每天在用；多年施工经验，做过智能布孔系统；
媒体出身，文案排版路演稿能兜。缺合约这块，想找搭子，娱乐为主。
```

填写纪律：只写本机能找到实物/截图的能力（`find` 产物文件、`command -v` 看装的 CLI），没产物的条目先问使用者确认；虚拟项宁可写"想找人搭"。
