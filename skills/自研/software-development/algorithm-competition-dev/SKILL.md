# 算法比赛开发（Algorithm Competition Dev）

## 触发条件
用户参加算法/数据类比赛（琶洲算法大赛、数据建模大赛等），涉及：选赛题、做方案、开发模型、准备提交物、压缩时间。

## 赛题选择（新手/时间紧时的判断标准）
- 优先"规则+寻路/优化"型赛题：评分点在逻辑合理性、阈值可解释性、路径质量（如低空无人机航线规划，规则阈值+A* 就能拿大部分分）
- 避开"深度学习预测精度"型赛题：评分大头压在预测准确度上，新手难拿高分（如水库72h水位预测、风光发电要素预测）
- 快速判断：评分结构里"预测准确度/精度"占比 >40% 的赛题对新手不友好；"可解释性/路径合理性/效率"占比高的赛题规则型方案就能打
- 数据可得性：组委会统一提供数据优先；自备数据要提交《数据来源声明》

## 开发流程（核心：框架先行，不等数据）
1. 评分点反推方案：把100分拆成"哪块容易拿"，写方案txt放桌面（用户习惯txt，不用md）
2. 框架先行：核心算法（分级模型/寻路/评估/可视化）不依赖数据格式，先写完并用 demo 数据跑通——数据审核期就是写框架期
3. 数据摸底：字段/时间范围/缺失率 → 出数据报告，再定网格分辨率等参数
4. 填数据调参：字段映射配置化（如 load_data.py 的 FIELD_MAP），数据到了只改配置不改逻辑
5. 评估+可视化+报告：报告是用户政务写作强项，能拉开差距；matplotlib 出图（风险热力图+3D航线）让评委直观
6. 提交物5样：主测试脚本（对接平台规范）/模型文件（规则型=阈值配置JSON，可加载可复现）/完整源码（PEP8+注释）/测试报告（含异常场景记录）/部署文件（requirements+部署脚本+README）。官方提交物清单、赛程表、众创平台 URL（zcpt.gd121.cn）、接入规范获取途径见 references/pazhou-meteorology-cup-official.md（注意：众创平台只管数据下载+作品提交，无在线训练环境）

## 时间管理（用户偏好）
- 倒排时间表，用户要求**提前1-2天交付，不卡截止日**（"跟河南创新创业大赛一样"）
- 数据下载/审核可能拖1-2个工作日 → 审核期内把不依赖数据的代码全部写完
- 用户对 token 费用敏感：大活（写代码/跑测试/批量调研）放在非高峰（12-14、18点后），或等用户发话再开工

## 关键坑（2026-08 琶洲赛题01 实战验证）
1. **气象要素阈值方向**：风速/降水"越大越危险"(direction=higher)，能见度/雷电距离"越小越危险"(direction=lower)。阈值配置必须带 direction 属性、分级逻辑按方向比较，否则全判错（曾导致全部判禁飞）
2. **网格化坐标**：经纬度必须先转平面 km 坐标（1°纬度≈111km，1°经度≈111×cos(lat)km），网格构建函数传平面坐标，不是经纬度（否则网格只剩1格）
3. **A* 单位一致 + 可采纳启发式**：g（累计时间）和 h（启发式）必须同单位（秒）；风场修正=地速=空速+风在移动方向投影（顺风快逆风慢），换层加时间惩罚。h 保持可采纳（admissible）：h 分母用 `speed + max|wind|`（最大可能地速），不能用固定空速——顺风时地速 > 空速，h 若用空速会高估剩余时间、破坏 A* 最优性（悄悄找到次优路径，飞行时长偏大）
4. **matplotlib 中文**：`plt.rcParams['font.sans-serif']=['SimHei']` + `matplotlib.use('Agg')` 无窗口出图
5. 插值用 IDW 即可（比赛交付优先），克里金/最优插值留作时间充裕时的加分项，别过度工程化
6. 平台规则先看：如"众创平台只提供数据下载与作品提交、不提供在线训练环境"→ 本地开发即可，不折腾云端
7. **netCDF4/xarray 中文路径（Windows 必备坑）**：netCDF4 底层 C 库 fopen 不支持中文路径——文件明明存在却 FileNotFoundError（os.listdir 正常=Python Unicode API，但 C 库失败）。修复：`subst X: "D:\中文路径..."` 映射虚拟盘符（不复制大体积数据），代码写 find_data_base() 自动探测 X 盘→回退中文路径。详细配方见 references/windows-netcdf-pitfalls.md
8. **git-bash 传中文给 `python -c` 会乱码**：找不到文件。修复：写成 UTF-8 .py 脚本文件再执行；路径用 os.listdir 逐层探测，别硬编码中文
9. **10G+ 大目录摸底别用 find 全遍历**（60s 超时）→ 分层 ls + 对代表子目录 du 测大小 × 数量估算总量
10. **nc 嵌套结构别按目录名猜**：如"每目录1天、每文件含24小时"（dims time=24,y,x），用 xarray 打开看 dims/coords/attrs、打印 time min/max 确认
11. **阈值校准法**：抽样每月5/15/25日×全天（≈30天/61.7万样本）算分位数；物理红线（禁飞=抗风6级10.8m/s）保持不动，中/高阈值按分布下调（风速 5.5/10.8→3.5/7.0，95分位3.19/99分位4.80）；降水4/8/16 与数据吻合就不动
12. **演示时次自动选择**：极端天气（禁飞30%+）时 A* 无路径=业务正确但演示效果差；自动挑"禁飞占比8%~35% 且 A* 可达"的时次（find_demo_scene 策略），先批量分类测试再选演示场景
13. **图片数据不可反推数值**：雷达/卫星给的是彩色渲染 png/jpg（无刻度元数据、数千色）→ 无法可靠反推 dBZ，标注"不可用"别瞎编；雷电要素缺失时阈值配置保留但 row 传 None（missing_policy=treat_as_low 不干扰 worst_case 综合）
14. **批量测试支撑报告**：多场景分类（晴好/小雨/中雨/大雨/暴雨）跑全流程，统计各类可行路径比例+平均禁飞占比，测试报告数字全来自真实运行（120时次样例）
15. **预报 netCDF 时次对齐（别用 hour 当下标）**：giftdaily 等预报产品按"数据块"存（每天 08块/20块），每块首时次=起报时刻+1h（实测 08块 time[0]=当天09:00，20块 time[0]=当天21:00），不是 00:00。用 `arr[hour]` 当索引会**静默错位 9~20 小时**——数据不对但程序能跑、平台能 PASS，风险识别结果全被污染。修复：构造目标时刻 `np.datetime64(day+'T'+hour)`，`np.argmin(|time - target|)` 找索引，偏差>1h 判"该块不含此时次"依次试当天08→当天20→前一天20→前一天08 块；glob 文件名用块时间戳匹配（前一天块文件名含前一天日期，用 day 匹配会漏）。完整配方见 references/route-planning-enhancements.md
16. **路径平滑（去 26 邻域阶梯折线）**：A* 输出是网格阶梯折线，可 Douglas-Peucker 简化，但删点前必须做"可见性检查"（line_of_sight：Bresenham 采样逐点查是否穿禁飞格；跨高度层段保守不直连），否则简化会把禁飞格拉进直线。配套增强：续航约束（总时长>上限置 endurance_exceeded 标记，路径仍返回业务层判不可达）、GeoJSON/航点导出（对接飞控/地图，评委一眼看出工程价值）、途中风险动态校验（沿路径按飞行时间采样未来时次预报）

## 交付验证
- 每个模块写 `__main__` 自测 + 最终一次性断言式验证脚本（放 D:\Temp\UserTemp，前缀 hermes-verify-，跑完即删）
- 交付前跑全流程：数据→分级→规划→评估→出图，确认无残留占位/无异常
- 明确告知用户：这是 ad-hoc 验证不是测试套件全绿（项目通常没有 pytest 套件）
- 用户说"写个东西给XX端跑/能不能直接交付XX" = 剩余任务直接派子代理(delegate_task)干完交付，别写交接文档让用户手动中转（2026-08 用户原话"你不能直接交付桌面端吗"；先干完再补一份说明即可）
