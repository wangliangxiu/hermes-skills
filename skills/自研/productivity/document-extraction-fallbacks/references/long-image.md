# 长图（超长截图）的读取，与"这张长图是怎么做出来的"

## 一、分段读取配方

可读窗口约 **622px 宽 × 900px 高**：比这更高的 crop 会被降采样（622×8018 整张直接压成 77×1002，字全认不出）。
宽度是原图宽度就够，不用放大——识图侧最终仍按约 622×900 处理，2 倍导出只多一步。
优先用识图工具的 `region` 参数（直接传原图 x1,y1,x2,y2）逐段读，不落盘；下面这段 PIL 切片只在工具没有 region 参数时才用。

```python
from PIL import Image
im = Image.open(path)                 # 先打印 im.size 确认总高
step = 860                            # 相邻条只重叠 60-100px
for a in range(0, im.size[1], step):
    c = im.crop((0, a, im.size[0], min(a + 960, im.size[1])))
    c.save(f"{tmp}/seg_{a}.png")       # tmp 用 $TEMP，别放桌面/项目目录
```

逐条送识图工具，指令用「逐字誊写这一段（含表格数字）」；要平台水印、UP 主名字这类元信息时，额外补一条只读顶部/某块区域的问法。
某条回不出文字（答复里只有"截图已移除"之类）就原样重发一次，通常就出来了。

## 二、边读边落盘（关键）

- 顺序固定：读一条 → 立刻把誊写追加进笔记文件 → 再读下一条。识图结果随后会从上下文里消失，不落盘就得重读。
- 追加用 `patch` 锚定文件末行；`write_file` 是整体覆盖，会把前面已读的段吃掉。
- 笔记文件放系统临时目录，汇总成答案后按需清理；用户要留全文时再整理成 txt。

## 三、来历判定：这张长图是怎么做出来的

看这几条证据即可下判断：

- 文字里有语音转写痕迹（同音错字、断句怪）→ 文字来自 ASR + 大模型整理，不是人手打的
- 结构化小标题带编号（原理1/2/3、投放时机1/2/3、4食物来源、5有氧运动）→ 大模型分节产物
- 白底文字段与视频原画截图交替、截图带平台水印和出镜人打码 → 按节抽关键帧当配图
- 文件名是 32/40 位十六进制哈希 → 在线工具导出的成品图，不是本地截图

标准生产流程（用户问"怎么做出来的"时照这个讲）：

1. 取视频/音频（yt-dlp 下 B 站链接，或用视频自带字幕）
2. ASR 转写
3. 大模型按主题重排：分节、起小标题、把表格数据抽成表
4. 抽关键帧截图（课件页、字幕页）
5. HTML/CSS 排成 600-700px 宽的纵向长页（白底文字块与深色截图交替），无头浏览器（Playwright/Puppeteer）整页截图导出长 PNG

现成工具路线（BibiGPT、Ai好记、通义听悟这类视频总结工具的"图文笔记 / 长图导出"）与本地自建路线都讲一句：本机 ffmpeg + 已有 ASR/vision 服务已覆盖第 1、2、4 步，自建只缺第 3、5 步的模板。

## 四、回答形态

- 用户说"总结一下，这个是怎么做到的"这类话时指代常是双关：既可能问内容，也可能问这东西怎么做出来的。先按主线把**内容**讲清楚，再单开一段讲**制作方式**，最后问一句要往哪边深挖——不要只答一边。
- 图里的错字、病句照实录，别顺手改通顺（改了就毁掉"这是自动转写"这条判据）；确需说明就用括号标注。
- 交付：长内容的总结可直接答，用户要留全文再落 txt；不要主动生成文件。
