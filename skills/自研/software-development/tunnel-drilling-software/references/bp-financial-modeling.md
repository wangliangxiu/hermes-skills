# BP 财务建模铁律（2026-08-13 使用者多次纠正 + 9条专业审查意见后固化，v3 已落地）

## 口径铁律（使用者原话级别的纠正，违反必被点名）

1. **台车造价 ≠ 软件造价**：市场规模/成本/盈利只算软件自己的账。
   台车调研数据（销量/价格/毛利）只作"软件可服务基数"参考，绝不充作软件收入
   （使用者原话"这个台车造价，不是咱们软件造价，要分开的"）。
2. **调研报告数据 = 参考，不是依据**：引用必须标注数据出处（报告名+页码）+ 假设条件，
   不冒充实测。写作铁律同款：查不到就写【待补】，不编数字。
3. **买断制不能简单对冲**："卖1套就回本"是伪命题——买断是一次性收入、维护是持续支出，
   必须按**单客户全生命周期成本**算（服务几年花多少，15万能否覆盖）。
   极端场景（全公司1客户+3年服务期）成本≈18.3万 > 15万会亏。
4. **变动成本按套累加**（10套=10份AI调用），不能做除法摊薄（使用者原话"不能做除法的"）。
5. **成本必须算全**：保险（商业险：软件产品责任险约1万+机械险约0.5万/年，不是社保！
   使用者明确"我说的不是社保，是保险——咱们软件和机械的保险"，即找保险公司投保的
   产品责任险）、税务（小规模：增值税1%+小微所得税5%）、部署标定差旅
   （2人×7天≈1.5万/次：交通0.3+住宿0.42+食补0.21+试爆0.5）、云服务器（2~5k/年）。
6. **利润离谱=不可信**：投入产出比失衡（开发4.8万第1年赚50万）评委一眼看穿 →
   销量保守化"先验证后放量"（第1年微利打平、第2-3年起量），并弱化"卖1套即过平衡点"
   的强调，改说"成本结构具备快速回正能力；当前核心任务是验证产品与市场匹配"。
7. **定价模式先问清楚再建模**：设备所负责人口径 = B2B 软件买断授权——**厂商15万买断一套，
   厂商自己配台车卖、卖多少台与咱们无关、不再分成**。不是"每台台车配一套软件"。
8. **AI 调用厂商自负**：在线AI功能厂商自配 API Key、费用厂商自负（否则成本裹不住，
   15万买断必亏）；备选：未来可调整为含AI费用的年费模式（B端客户可能想要一口价全包）。
9. **对外材料统一"合作厂商"**：不点名具体厂商（洛阳中铁强力等）；
   数据出处写明（理由+公式+出处）。成员实名：设备所所长 = 明工（3号成员）。

## 成本公式模型（v3 最终写法——使用者口径"固定成本 + 每套卖多少"）

```
总成本 = 固定成本 + 每套变动成本 × 套数（套数 = 签约厂商数，不是台车数！）
收入   = 套数 × 15万（买断）
利润   = 收入 − 总成本 − 税费
```

- 固定成本：初期研发 4.8万（一次性，4人×6k×2月；**标注兼职/项目制+基本生活补贴**，
  否则评委质疑人力成本偏低）+ 产品迭代 1.5万/年（新增功能/适配新台车型号）+
  维护 3.6万/年（1人×3k/月，咱们持续维护）+ 服务器 0.4万/年 + 保险预留 1.5万/年
  → 首年 10.3万，此后每年 7万
- 单套变动成本：部署+标定+差旅 1.5万/家（2人×7天，**基于省内/邻近区域估算，
  远程项目会上升**）；AI 厂商自负 → 软件方零 AI 变动成本
- 单套毛利 = 15 − 1.5 = 13.5万
- 盈亏平衡：首年 10.3/13.5 ≈ 0.76套；此后 7/13.5 ≈ 0.52套（卖1套即过，但措辞弱化）

## 销量口径（审查意见问题6/7 后统一：套数 = 厂商数）

- **套数必须统一为签约厂商数**（买断授权），不能与台车数混用。
  全国主要凿岩台车厂商约 7~10 家（鑫通/耿力/泰鑫/钻神/五新/蓝海/正讯等）。
- 厂商数假设（保守，从合作厂商起步）：第1年1家（合作厂商，配套其年销5台全电脑
  双臂台车，渗透率100%）、第2年3家、第3年5家。
- 台车销量数据仍作为**需求依据**：国产台车年产量参考约1100台/年（单臂470+双臂630，
  《凿岩台车调研情况汇报2026》第18/30/47页）证明厂商有动力采购布孔软件。
- 财务结果（1/3/5家厂商，含保险+小规模税+迭代费）：
  第1年 收入15万 → 税后 **2.9万**（验证期微利）
  第2年 收入45万 → 税后 **31.4万**
  第3年 收入75万 → 税后 **56.8万**

## 税务口径

- 小规模纳税人：年销售额 15~75万 < 500万标准 → 增值税按 1%（季度销售额≤30万
  部分可免征，**集中交付时需复核免征边界**）；企业所得税按小微优惠（应纳税所得额
  ≤300万部分实际税负约5%）。
- 脚注必须写"按现行小规模纳税人优惠政策估算，实际以税务政策为准"（政策可能调整）。

## 保险口径

- 商业险（软件产品责任险约1万/年 + 机械险约0.5万/年 = 1.5万/年），
  写为"预算预留项，实际按需投保"（初创早期无大规模部署不强制，避免被质疑）。

## python-docx 编辑 BP 的技术坑

1. **段落整段替换**：删所有 run → `p.add_run(line)` + `run.add_break()` 处理换行，
   设置 font.name='宋体'（保留段落样式）。
2. **insert_paragraph_before 会命中目录里的标题**！`insert_paragraph_before('4.4 盈利预测')`
   匹配到的是**目录区**的第一个"4.4 盈利预测"（文档开头），段落被插进目录。
   正确做法：定位正文锚点段（用唯一正文文本片段），
   `anchor._p.addnext(OxmlElement('w:p'))` + `Paragraph(new_el, anchor._parent)` 插到指定段后。
3. 定位段落用"正文独有文本片段 in p.text"，避免匹配目录/页眉。
4. **替换前必须读实际段落文本**：预期"约2000~5000元/年"实际是"约5000元/年"
   （中途改过），old_frag 不匹配会静默"[未找到]"，save 后文档少一段——先读再改。
5. 每次改完 docx 立即重新读回验证（python-docx 重开文档打印目标段），
   发现插错位置立刻修复（删误插段 + 重插）。
6. 改文档的临时脚本放项目目录、用完即删，不留桌面（使用者规矩）。
7. BP 只留最新版：新版本生成且使用者确认后删旧版。

## 9条专业审查意见（2026-08-13 使用者贴来，已全部落地）速查
