# 链上可验证随机（红包/抽签类）与独立复算

适用：任何把"随机分配"搬上链的项目（拼手气红包、抽签、随机奖励）。核心卖点是一句话：
**中心化红包的随机你只能信它，链上的随机你能自己验。** 这个卖点只有在"输入全公开 + 有独立复算工具"时才成立，缺一样就等于撒谎。

## 一、合约侧设计

份额公式（经典"拼手气红包"约束 + 可复算随机）：

```
last 份（left <= 1）：直接拿 remaining，避免零头
其余份：
  maxShare = remaining * 2 / left          // 不许超过平均值的两倍，防一人独吞
  base     = (remaining / left) * tierBps / 100   // 平均份 × 档位系数
  r        = keccak256(prevRandao, receiver, poolId, index, tierBps)
  share    = base * (60 + r % 81) / 100     // 在 60%~140% 之间浮动
  share    = clamp(share, 1, min(maxShare, remaining))
```

- 随机源用 `block.prevrandao`，**不要用 `blockhash(block.number - 1)`**：后者只在最近 256 个区块内可查，过期后没人能验证，卖点直接失效。
- 事件必须携带全部输入：`Grabbed(poolId, receiver, share, prevRandao, grabbedIndex, tierBps)`。
- 把 `shareFor(...)` 写成 `public pure` 函数，链下能直接调它核对，也方便写成测试断言。
- "档位系数"这类外部参数随建池交易一起上链（写进池子结构体），不要留在后端——否则复算者拿不到它。

## 二、最容易砸穿"可验证"的两个 bug

1. **计算用的序号 ≠ 事件里记的序号**：`grab()` 里若先自增再发事件，事件的 `grabbedIndex` 就比实际参与哈希的索引大 1，外部复算全部对不上。写法：先 `uint256 idx = p.grabbed;` 用 `idx` 参与计算与发事件，自增用 `p.grabbed = idx + 1;`。
2. **随机源不可回溯**：见上，用 `prevrandao`。

## 三、独立复算器（第三方/评委可自己跑）

工具化，别只写在文档里。步骤：

1. 按交易哈希取 receipt，从日志里解析出事件参数（`process_receipt` 返回的是列表，取 `[0]`；w3 v8 下 receipt 本身没有 `logIndex`，索引在事件条目里）。
2. **还原那一刻的池子状态**（只依赖链上公开数据）：把所有同池子的历史事件按 `(blockNumber, transactionIndex, logIndex)` 排序，取本次之前的那些 —— `remaining = total - sum(之前份额)`、`left = count - 之前条数`。
3. 用与合约**同一套公式的 Python 镜像**复算，与链上记录的份额比对并断言相等。
4. 输出里把公开输入逐条列出（随机数、地址、池子/领取序号、档位系数），让读者能自己手算。

## 四、本地链测试清单（上测试网之前必须全绿）

- 部署 → 建池 → 多人依次抢 → 份额总和 **正好等于** 池子总额（一分不多一分不少）
- 每一份都用 Python 离线复算，与链上一致（这是"可验证"的自动化证据）
- 核销后可用额度递减；花超过自己名下的份额被 revert
- ABI 里不存在任何 transfer/approve 类函数（不可转让的机器证据）
- 工具本身也要用一笔真实交易验证一次（复算器自己错了等于没有）

## 五、演示可用性（别只顾契约正确）

- 合约常有"同一地址只能领一次"的约束；多人演示时要按**未领过的账户轮转**（本地链用助记词派生多个账户，后端挑第一个未领的当"当前访客"），否则第二次点击就 revert。
- 准备一个"重开一包"的脚本（新建池子），演示前把池子重置；后端默认取**最新建立的那个池子**，避免写死编号。
- 前端把"这一次份额的公开输入"直接展示在界面上（配上复算命令），演示时指着它讲比讲原理有效。

## 六、排错对照

| 症状 | 原因 |
|---|---|
| 外部复算总差一点点 | 事件里的索引与参与计算的索引错位 |
| 复算在旧交易上算不出 | 随机源用了 blockhash 而非 prevrandao |
| 第二次演示 clicking 就失败 | 地址已领过（合约防多领），需换账户或重建池子 |
| 复算器读不到池子余量 | 用当前状态而非"本次之前"的历史状态还原 |
