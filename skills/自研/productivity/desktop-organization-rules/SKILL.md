# 桌面文件管理规范

## Overview

使用者使用者的 Windows 桌面文件管理规则。
每次生成文件、小程序、项目时，按分类归入对应文件夹，不在桌面散放多个文件。

## 文件夹结构

桌面路径：`C:\Users\使用者\Desktop\`

### 现有文件夹

| 文件夹 | 用途 |
|--------|------|
| 我的小项目/ | 所有做过的项目合集（摸鱼万年历、采编、四季合合等） |
| Python学习/ | Python学习相关文件（hello.py等练习文件） |
| 大模型学习计划/ | 学习进度Excel表格 |
| 简历模板/ | 简历相关文件 |
| 青年科技大赛/ | 比赛相关资料（人员档案、商业计划书等） |

### 文件归属规则

1. **Python练习文件** → `Python学习/<项目名>/`
2. **学习计划表格** → `大模型学习计划/`
3. **做的小项目/工具** → `我的小项目/<项目名>/`
   - exe、zip 等单独文件 → 先建项目文件夹再移进去
4. **自传/操作指南等文档** → 直接放桌面（使用者要发给别人），旧版必须删除
5. **临时脚本**（用完即删的生成器）→ 跑完后立即删除，不留痕迹
6. **比赛/报名类文档**（txt/xlsx/docx）→ `青年科技大赛/` 文件夹
7. **学习汇总/笔记类文件**（给其他AI的上下文）→ 建 `给deepseek/` 或 `学习汇总/` 文件夹归入对应学习计划目录
8. **交接/带走类包**（要给另一台电脑、另一个 AI，或发给别人接着干）→ 桌面根目录建一个 `<任务名>交接包_<日期>\` 文件夹一次装完，同时出一个同名 `.zip` 方便拷走；包内文件不在桌面散放
9. **分析/评估/回信类任务产出**（评估报告、给对方的回信初稿、素材汇总）→ 建 `我的小项目/<任务名>/` 一起装；要外发的成品在回复里直接写绝对路径给使用者，不在桌面散放
10. **要加工的素材**（使用者给的一批照片/图片/文档）→ 产出、观察笔记、缩略图统一建 `我的小项目/<任务名>/`；素材本身就地重命名/编号可以（如照片排镜号），但**「原文件名 → 新文件名」对照表必须写进产出文件**，并在回复里念一遍，使用者随时能改回

## 更新原则（重要）

- **每次更新文件，必须先删除旧版本**
- 不留「方案_v1」「方案_v2」「方案_最终版」
- 桌面上每个用途只保留 **最新一个文件**
- 如果用户问"之前那个文件呢"，先检查有没有移到文件夹里了

## 新建项目流程

1. 先建文件夹：`我的小项目/<项目名>/`
2. 把所有相关文件移进去
3. 如果项目只有一个文件，也需要建文件夹包起来
4. 不在桌面散放单个 `.py` `.exe` `.zip` 文件

## Common Pitfalls

1. **桌面堆文件** — 生成新文件后不及时归位，桌面越来越乱
2. **保留旧版本** — 更新指南/文档后不删旧版，用户分不清哪个是最新的
3. **不留临时脚本** — 用来生成表格的 `.py` 脚本跑完就要删，不要留在桌面上
4. **忘记已有文件夹** — 建新文件夹前先检查桌面已有结构，避免重复
5. **中文路径骗过退出码** — 本机所有路径都在 `C:\Users\使用者\` 下含中文，处理类工具（OpenCV/cv2、部分 CLI）读不进去，报“无法读取/文件不存在”而**退出码仍为 0**。要处理的素材先拷到纯 ASCII 暂存目录（如 `D:\ascii_tmp\`）再跑，成品拷回项目文件夹；判成功只认“输出文件存在 + 肉眼看过”，不拿 rc=0 当证据
6. **删大文件不吭声** — 清自己下的临时文件时，删任何 >100MB 的东西要单独一句话写清“路径 + 是什么 + 为什么删”；混在进度汇报里会让使用者以为动了他的东西
7. **改名不留退路** — 就地重命名使用者的素材（照片排镜号、批量整理）本身没问题，但不写对照表＝使用者找不回原文件。对照表进产出、回复里再念一遍；不要另存一份副本充数（白占空间）
